# V2 架构、构建与接口

新版网页采用浅色运行总览与侧栏布局，账号查询、全池筛选、任务历史及 CPA 同步连接实际后台。源码已接入批量随机延迟、定期及窗口到期额度查询、模型与短句池配置、手动候选生成和 Codex 模型唤醒；自动查询及自动唤醒默认关闭。模型唤醒与可编辑生成提示词自 rc.8 提供，rc.7 不包含。界面、数据口径和验证方法见 [V2 网页面板](../user/panel.md)。

当前后台、客户端和接入层均为 v0.2.0-rc.28，数据库为 schema 12。已实现独立后台及 C 原生接入层，并有本地假宿主端到端测试；曾以空账号 CPA 隔离实例验证注册与管理转发，尚未完成真实账号查询或模型请求验收。当前部署步骤见 [安装指南](../user/install.md)，总体目标见 [重建设计](design.md)，接口约束见 [实施契约](contracts.md)。

## 已实现

- 独立 `window-refreshd`：Go 后台，SQLite WAL/FULL 持久化，本地 Unix socket HTTP API，内嵌 HTML/JS/CSS。
- C ABI 1/schema 6–7 接入层：原生 pthread 工作池，受限账号读取、额度 HTTP 及模型回调，大小限制、同 UID 校验、有界排队和排空后卸载。没有 Go 运行时和 `RTLD_NODELETE`；schema 7 起省略请求拦截正文。
- CPA 管理/资源路由转发到后台，继续使用原页面入口；管理密钥不向后台转发。状态码、响应体、Content-Type、查询参数及幂等键经过实际转发测试。
- 单账号和全账号只读额度任务：先持久接受，再展开和执行；按任务 ID 读取逐账号结果；重复幂等键返回原任务，内容不同时冲突。
- 不同账号并行，同账号需求复用一次在途查询；数据库事务不等待网络。查询并发可由 CLI 设置为 1–128，原型默认 8，默认值尚未经过生产负载校准。
- 后台读取 CPA 账号绑定，按该账号实际代理查询固定额度接口，未指定账号代理时通过宿主 HTTP 继承 CPA 全局代理；显式 direct/none 仍直连。查询后再次核对账号身份。只把归一化的允许字段写入数据库，token 和原始凭据不落盘。
- 支持 `host.auth.models` 的宿主通过后台提供精确账号模型目录；仅明确不支持或旧接口缺失时回退管理接口。目录查询不读取凭据、不试发模型，不改变手动模型配置和发送规则。具体实现与验证见 [API 优化记录](../research/cpa-api-optimization.md)。
- 后台重启保留原任务 ID、结果及幂等记录，重新安排被中断的只读任务。宿主回调仍在执行时接入层暂停失败并保留所有权，回调返回后才能释放。
- 请求开始、账号选择和完成事件：钩子只提取请求 ID、允许的身份摘要、账号 ID 及时间；不解码或保存正文，不保留认证头。钩子不等待后台或数据库，返回空修改结果。
- 事件按接入实例和递增序号重放，后台在同一事务提交活动与水位后才 ACK。后台断开后可补入缓冲内事件；溢出、接入层重载或确认水位不一致均暴露缺口。
- 一致的读事务与带版本账号分页；页面拒绝过期响应和旧后台实例，跨页数据变化时重新读取。活动摘要每 5 秒刷新，失败时保留数据并提示陈旧。
- 有限保留的任务历史、独立幂等回执及活动索引；源码 schema 1–11 自动迁移到 schema 12，保留已有 v2 任务。查询规则、逐账号随机期限、绑定、调度水位、模型配置、候选生成快照、唤醒计划及共享模型保护持久保存，重启不重新抽取查询期限；旧任务保留原提供方及默认提示词语义，不重发结果未知的模型请求。已发布 rc.7 的库仍为 schema 6。
- 手动单账号无随机延迟，可提前执行同账号排队需求；手动批量与自动查询由后台按账号抽取延迟。定期、五小时和周到期查询分别启用，支持时区及排除时段；查询队列与后台生命周期不依赖浏览器。
- HTTP、流式头初始化及 Codex WebSocket 额度观测；后台独立同步 CPA 本地账号，按字段合并证据，防止慢查询覆盖新业务观测。

rc.8 为候选生成及受控唤醒复用三个有界模型流方法，不开放其他模型方法。候选生成支持指定 Codex 或反重力账号，唤醒仅支持 Codex；两者共享数据库中的物理模型预算及账号保护，不允许以两个任务类型绕过在途或未知发送抑制。反重力使用独立生成账号目录，不进入 Codex 额度池；提交和派发前复核提供方及运行时身份摘要，不回退到其他账号。

接入层通过 `prompt_generation_providers` 声明候选提供方，通过 `wake_supported` 单独声明唤醒能力；只有旧生成布尔能力的接入层按仅支持 Codex 候选处理，不能据此启用唤醒。管理路由的权限及后台准入仍需分别核对。`model_execution` 表示模型唤醒执行能力，不表示自动规则已开启；手动生成由 `prompt_generation` 单独标记。桥接握手和健康检查的 `read_only` 为旧协议兼容字段，不是“所有功能绝不调用模型”的安全声明。

唤醒先持久接受，再只读预检、准备、发送和只读核实。自动总开关及五小时、周、每日规则默认关闭；开启后，后续额度查询或正常业务产生的新观测可能触发独立唤醒任务，查询本身仍不发送模型。手动操作也不能绕过账号禁用、绑定、额度、活动和未知发送保护。模型确认完成与窗口核实分开记录，结果未知只允许只读核实，不因重启自动重发。完整规则和 API 见 [面板说明](../user/panel.md#模型唤醒)。

业务路径通过本地假宿主验证不等于真实账号验收。按部署约定不导入 v1 数据，成功后清除旧版数据。新库不能用旧二进制直接降级，须恢复升级前一致备份。已发布包仍以发布说明为准，普通 v1 更新不会自动切换。

## 正常业务额度与绑定

后台启动后同步 CPA 本地账号，之后每 30 秒刷新一次；使用 8 个工作协程读取运行绑定和账号 JSON，只保留账号 ID、auth index 与上游账号 ID 的 SHA-256 摘要。没有可用 token 的账号仍可建立只读观测绑定，但手动查询会报告凭据缺失。单个坏账号标记 `binding_unavailable`，不会阻止其他账号。账号缺失后标记 removed，并清除其额度。概览和页面展示账号同步状态。

每轮完整核对后更新统一同步心跳；未变化的账号行不重复写入，绑定确认时间每 5 分钟形成检查点。状态新鲜度同时参考账号行和同步心跳，旧查询结果不能覆盖较新的完整同步。身份核对频率与接入层绑定过期规则保持不变。

接入层只缓存已提交到数据库的绑定摘要，额度响应按 credential selection 时捕获的摘要归属。后台刷新发现绑定变化时，使旧请求映射失效，数据库再次核对摘要；接入层的绑定视图在 90 秒后过期。该机制不能代替宿主权威凭据代际：同步间隔内的变化、同一 ID/index/上游账号重新登录，以及宿主未提供尝试 ID 时的部分重试交错仍无法被完整识别。绑定视图仅提供观测归属，模型发送仍需独立预检和事务准入。

普通 HTTP 只采集允许的额度响应头；流式响应仅处理 `ChunkIndex == -1` 的头初始化。重复头及普通内容块不推进额度时间。WebSocket 只接受明确 Codex provider、匹配账号的 `codex.rate_limits` 或带额度头的 `error` 事件；只解码有界事件并提取允许的标量额度字段。原生请求映射最多 4096 个槽，哈希碰撞时会漏掉被替换请求的被动额度，不会把其响应归给新请求。普通绑定 10 分钟过期，完成后保留 2 分钟，以兼容完成事件早于响应钩子的情况。

额度与事件水位在同一事务提交。每个权限/窗口字段保存独立的 `source`、`observed_at`、`read_started_at`，只接受读取边界更新的证据。查询在 HTTP 开始前记录读取边界；较早查询晚返回时，可以完成原任务，但不能覆盖较新的业务字段。缺失字段保持原值与原时间。现有 schema 2 中尚无绑定索引的额度，在首次建立新摘要时会失效并等待新观测；任务和幂等记录保留。

钩子返回空修改结果，符合固定版本 [CPA SDK 的响应修改契约](https://github.com/router-for-me/CLIProxyAPI/blob/3de4e248f6bb12fc7dfafb183404f3b248578922/sdk/pluginapi/types.go#L1118)：不改写响应头、不替换正文、不丢弃流块。账号读取、额度 HTTP 和 SQLite 工作均在钩子以外执行。

## 活动统计的边界

新版页面不再展示近期活跃用户数；后台仍保留近期 30 分钟已观测身份、已观测在途请求和未知占用作为诊断证据。现有 CPA 不提供权威的初始在途快照，因此 `baseline_complete` 始终为 `false`。连接正常或缓冲连续，仅证明观察开始以来的投递状态，不能证明启动前没有业务请求。

同一接入实例下后台重启，从持久水位继续；同一 CPA 进程中的接入层重载，把旧在途记录改为未知。仅当 CPA 进程身份确实变化时才解除旧进程占用；新进程的初始基线仍未核实。缺口不会因一次重连或一次新请求自动清除。超过 24 小时没有完成事件的在途请求变为未知，不把 TTL 当成成功完成。

内部模型回调及明确 `generate=false` 的请求不计入业务身份。未知请求的完成事件不能凭空增加身份数；已完成请求的迟到开始事件不能重新制造占用。自动五小时容量需求使用后台已观测身份，网页不展示这些人数。唤醒检查已有活动、未知占用与事件可信性，不能把 `connected=true` 当作全局无在途请求证明；没有 CPA 级原子互斥，仍不能完全排除预检后刚到达的业务请求。当前没有管理员强制清除未知占用或未知模型发送的接口。

## 保留与资源预算

| 数据 | 当前预算及行为 |
| --- | --- |
| 原生未确认事件 | 最多 4096 条、总计 4 MiB、单条 4 KiB；单个额度载荷最多 2 KiB；每批最多 128 条；超限回收产生缺口 |
| 原生宿主调用 | 8 个普通在途调用，额外保留 1 个 HTTP 取消调用位置，10 个处理线程；最多 8 个未释放 HTTP 操作。已进入宿主的调用超时仍占槽，按期限取消，退出时排空后才能卸载 |
| 原生额度绑定 | 最多 10000 个账号摘要和 4096 个请求映射槽，不保存凭据 |
| 后台在途及未知请求 | 合计最多 4096 条；超限记录可信性缺口，不继续增长索引 |
| 近期身份索引 | 最多 8192 个身份；超限暴露缺口；定期回收非活跃旧身份 |
| 已完成请求去重 | 最多 8192 条，定期删除 24 小时以前记录 |
| 任务历史 | 默认保留 7 天且目标最多 10000 个终态任务；活动任务不裁剪 |
| 管理幂等回执 | 至少保留到接受后 30 天；最多 50000 条；满时拒绝新任务，旧键仍可核对 |

维护在启动时及每分钟执行，任务历史、孤立查询记录和过期回执每轮最多清理 256 条，避免大事务阻塞控制请求。因此历史条数和年龄是逐步收敛的保留目标。SQLite 删除后的空间用于后续复用，不承诺数据库文件立即缩小。

任务详情已被裁剪且回执仍有效时，同键重试返回 `410 job_expired`，不会悄悄创建另一次任务；请求内容不同时仍返回 `409 idempotency_conflict`。30 天后且任务详情和回执均已回收，客户端不能再依赖该键去重。仍在执行的任务及其回执不会按历史期限清除。

## 构建

目标为 Linux amd64/arm64，需要 Go 1.23+、CGO、C 编译器、pthread、libcurl 开发包，以及 json-c SONAME 5。Go SQLite 驱动固定为 `github.com/mattn/go-sqlite3 v1.14.52`，使用随依赖提供的 SQLite，不要求系统 SQLite 开发头文件。

Debian 12/13 的原生构建依赖对应 `build-essential libcurl4-openssl-dev libjson-c5`，Go 依赖由模块文件管理。

```sh
make v2-build
```

产物：

```text
bin/window-refreshd
bin/codex-window-refresh-v2-bridge.so
```

这些使用独立构建目标，现有 `make plugin`、v1 安装器与发布包不切换到 v2。

## 本地验证

```sh
go test -race ./internal/v2/...
make v2-smoke
make v2-panel-browser-check
```

`v2-smoke` 用 Python ctypes 加载真实 C 动态库，启动真实后台进程，并使用临时 SQLite 与 Unix socket。假宿主的固定 Codex 查询账号没有 access token，额度预检在发出 HTTP 前失败；模型流只有显式测试开关开启后才返回内存数据，不调用真实模型。唤醒负向测试核对这种预检失败保持只读且不发送模型；正向测试通过原生被动额度头生成新鲜到期证据，由真实后台准入后调用内存模型流，再通过活动窗口证据完成只读核实。中断恢复测试仅在停机的临时数据库植入 `sending` 状态模拟崩溃，不伪造 `prepared` 来绕过准入。完整成功 HTTP 预检由 Go 注入 transport 验证，不能给假宿主填真实凭据或把固定额度接口改到真实账号。

原生测试覆盖：ABI 结构复制、禁止的模型方法和交叉协议拒绝、错误实例拒绝、帧长度拒绝、并发宿主读取、CPA 页面转发、任务及幂等记录跨后台重启、状态码/二进制体/查询参数转发、认证头剥离、暂停超时保留所有权和安全 dlclose；另外验证大请求正文不进入事件、事件不可变重放与 ACK、4100 条事件触发有界溢出、内部请求过滤、停机期间的完成事件补入，以及接入层重载后的未知占用。新增唤醒检查覆盖设置默认关闭与冲突、无模型副作用的只读失败、精确指定账号与已保存提示词、不夹带候选生成指令、发送成功后仍待核实、真实活动证据解除保护，以及未知结果跨重启阻止新唤醒和候选绕过；包元数据独立核对唤醒能力与未改变的 CPA 协议版本。

Go 测试另外以注入 HTTP transport 验证成功额度解析、敏感字段不落入快照、查询期间账号替换拒绝、慢账号隔离、同账号查询合并、提交结果幂等和中断只读任务恢复，并覆盖提交失败不 ACK、ACK 丢失恢复、缺口保持、分页冲突、保留回执和 schema 迁移。位于 `tests/web/v2/` 的 Node 测试验证旧响应、旧后台实例和读取/写入交错的页面版本保护。成功 HTTP fixture 测试不使用真实凭据。

## 单独运行后台

```sh
bin/window-refreshd \
  --runtime-dir /absolute/private/run \
  --data-dir /absolute/private/data \
  --query-concurrency 8 \
  --query-timeout 15s \
  --history-retention 168h \
  --terminal-jobs 10000
```

数据和运行目录不存在时创建为 `0700`；已有目录必须属于运行用户且权限为 `0700`。服务只监听 `<runtime-dir>/daemon.sock`。访问本地健康检查：

```sh
curl --unix-socket /absolute/private/run/daemon.sock http://localhost/healthz
```

`healthz` 验证后台与数据库，不能证明 CPA 接入或上游额度可用。没有接入层时任务保持明确的依赖阻塞，达到从接受时起 2 分钟的依赖等待期限后失败。

当前原生接入层以 CPA 进程环境变量 `CWR_V2_RUNTIME_DIR` 获取相同的私有运行目录。v2 安装器统一生成后台服务及 CPA 环境 drop-in，首次显式重启 CPA；验证成功后清除 v1 遗留数据、旧版本和临时恢复副本，后续保留 v2 数据。原生测试以模拟服务控制器验证实际包的首次安装、仅重启后台的更新、任务保留和健康失败后的 SQLite 恢复。rc.5 另在 Ubuntu 22.04 按非 systemd 方式运行官方 CPA v8.0.32 空账号隔离实例，核对实际注册、网页与管理认证、设置保存及冲突、后台重启恢复与 schema 4；未执行真实账号查询或模型请求。systemd 实机安装及真实账号仍待验收，自动安装器的系统支持范围仍仅 Debian 12/13。

| `GET /api/v2/accounts?after=...&limit=100&revision=...` | 同前缀及查询参数 | 按 ID 分页，校验账号视图版本 |
| `GET /api/v2/account-models?account_id=...` | 同前缀及查询参数 | 只读核实指定账号的已注册模型，返回账号 ID、provider 和模型列表 |

概览、查询任务和账号响应包含 `instance_id` 与 `view_revision`；唤醒详情包含 `instance_id`，唤醒列表还包含 `view_revision`。账号列表另返回 `accounts_revision` 和 `next_after`；首屏可以不传修订，后续页必须原样带回 `accounts_revision`。账号绑定或额度变化返回 `409 view_changed`，客户端重新从首屏加载；任务进度或活动事件变化不使账号分页失效。

创建任务必须携带 `Idempotency-Key`，正文为：

```json
{"kind":"quota_query","account_id":"actual-host-account-id"}
```

省略或清空 `account_id` 查询全部 Codex 账号。拒绝其他 kind、未知字段和过大请求。当前实现使用固定注册路径加查询参数，避免假定 CPA 支持动态任务路由。

## 业务执行记录与分流分析（schema 12）

原生 `scheduler.pick` 在现有内存选号锁内提取有界决策事实，向原生事件环提交 `decision` 事件；既有钩子补充逻辑请求开始、选择和完成元数据，`usage.handle` 只读取允许的执行 UUID、selection/trace ID、账号、模型、状态、耗时与用量字段。禁止读取或复制 APIKey、错误正文和请求/响应正文。宿主内部模型及 `generate=false` 不进入正常业务用量记录。

后台在原事件事务中更新 `traffic_requests`、`traffic_attempts` 和连续水位，提交后 ACK。逻辑请求以接入实例和宿主 RequestID 隔离；物理执行以实例和 UsageRecord.RequestID 去重；selection ID 连接决策及执行，不能把同一 selection 下的不同执行 UUID 合成一次调用。缺少 selection 时，只在同一实例的 trace 唯一且没有歧义时关联；出现 trace 冲突时撤回该回退关联，绝不按时间猜测。调用方及会话摘要采用每数据库随机盐，原始标识不进入流量表。

`GET /api/v2/traffic` 及对应 CPA 管理路径支持 `kind=users|plugin|analysis`，列表和聚合支持 `search/project/caller/account/model/status/session/from/to/page/limit`，详情使用 `id`（兼容 `request_id`）。响应含 `instance_id`、`view_revision`、`coverage`、真实统计、分页和可选详情；未报告的耗时/用量是 JSON null。筛选账号和分流原因匹配请求内任何实际执行尝试。账号、项目、调用方及会话聚合各最多 32 项，每行最多 32 个账号；`aggregation_limited` 和 `facets_limited` 指明裁剪，避免超过接入层 2 MiB 响应预算。聚合汇总保持完整保留范围口径。

插件调用视图目前由持久查询运行、唤醒响应、候选生成和重置卡操作派生，不能重建旧版本没有采集的网络尝试。新唤醒在授权发送的同一事务保存规则版本、绑定/额度/活动检查结论、查询证据时间及适用的容量缺口；不将后来的额度状态冒充发送时快照。查询共享运行只展示一次，并可关联多个任务。

请求及尝试上限为 50000/100000，达到上限保留安全活动链路并暴露流量缺口。历史维护沿用每轮 256 条的清理事务，逻辑请求按历史保留期和终态预算清理，孤立尝试一小时后可清理；无完成证据不会因保留时间被宣称成功。当前覆盖依赖宿主相应生命周期、选号和用量事件，空清单或模拟测试不代表真实业务观测已经完整。

锁顺序为 scheduler lock → event ring lock；usage/lifecycle 钩子先释放 scheduler lock 再操作 event ring，持有 event ring lock 时不回调选号器。钩子不等待后台、网络或数据库，序列化超长与环缓冲溢出继续报告 loss_epoch/gap。新增假宿主端到端测试验证决策 → 执行 → 持久请求/分析 API、摘要隐私、无真实模型调用；Go 测试覆盖重放、迟到决策、同 selection 多执行、换号恢复、未知结果和保留清理。
