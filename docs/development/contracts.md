# 后端 v2 实施契约

状态：V2 实施契约，当前实现范围见 [架构说明](architecture.md)。以 [重建设计](design.md) 为总体方案。本文件将可直接确定的边界写成开发契约；宿主行为待验证的项目列在最后，不把计划当成已实现能力。

## 1. 组件与配置的唯一归属

| 内容 | 唯一拥有者 | 其他组件的行为 |
| --- | --- | --- |
| 账号凭据、OAuth 刷新、正常业务路由 | CPA | 后台按需读取现有接口提供的信息，不刷新或改写凭据 |
| 管理入口认证 | CPA | 接入层只转发已注册管理路由，移除不必要的认证头 |
| 规则、生效配置、任务、操作及证据 | 后台业务数据库 | 页面读取 API，接入层不缓存业务真相 |
| 当前宿主 callback 与流句柄 | 接入层，实际执行归 CPA | 后台用实例和操作 ID 引用，不直接操作原生指针 |
| 前端资源和前后端协议版本 | 后台发布包 | CPA 资源入口转发；接入层不随网页更新 |

后台启动配置只保存数据目录、socket 路径、日志和资源预算等部署信息。业务配置经 API 校验后事务写入数据库，数据库提交成功才报告新修订生效。配置文件导入和导出是显式操作，不能同时维护 YAML 与数据库两份可写的生效策略。

接入层配置只包含连接路径、协议和资源预算。首次部署不导入 V1 规则或状态，成功后清除本插件的 V1 数据与临时恢复副本；后续通过新版管理界面维护 V2 规则。升级前需另行保存一致备份，详见 [安装指南](../user/install.md#备份与回退)。

额度查询默认由后台通过账号实际代理发起，目标仅限实现中允许的额度接口。CPA 提供账号身份和可读取凭据，后台不存储或记录 token。现有 `host.auth.get` 可能读取物理文件，不能将其宣称为内存最新凭据；失败时重新核对绑定和凭据，仍不可用则报告具体阶段，不自行调用 OAuth 刷新。

模型请求继续使用 CPA 的精确账号执行接口。浏览器、规则计划器和普通 worker 都不能通过普通路由猜测目标账号。

## 2. 本地连接与进程启动

两端各拥有自己的监听端点：

| 端点 | 监听者 | 客户端与用途 |
| --- | --- | --- |
| `daemon.sock` | 后台 | 接入层转发页面和管理请求；使用 HTTP/1.1 over Unix socket |
| `bridge.sock` | 接入层 | 后台读取宿主事件、查询原生调用状态并提交允许的宿主操作 |

系统服务由安装器创建私有运行目录；用户服务使用该用户的运行目录；容器显式挂载私有 socket 目录。socket 所属用户与连接对端必须匹配，数据目录与运行目录分开。只允许拥有者在校验文件类型和现有监听状态后清理自己的旧 socket，不能删除仍存活的端点。

后台和 CPA 可以任意先启动。接入层不等待后台启动才让 CPA 正常服务；后台无法握手时继续提供健康与管理视图，宿主依赖任务显示 blocked。连接按有上限的退避重试，重连成功后先校验宿主实例、事件连续性与原有在途操作，再领取新模型任务。

后台使用独占进程锁；持锁期间才可领取和授权模型任务。后台服务管理器负责生命周期，CPA 插件不反复 fork 后台子进程。日常更新只重启后台；升级接入层才涉及 CPA 生命周期。

## 3. 宿主操作协议

`bridge.sock` 使用有长度上限的帧：4 字节大端长度加 UTF-8 JSON，连接按控制、事件和宿主操作用途分开。以下为本项目协议，名称不代表已有 CPA API。

请求包括：

```text
protocol_version
request_id              单次协议交互身份
operation_id            一次业务模型调用或只读操作身份
action_id               此次原生方法调用身份
owner_epoch             当前后台执行权代际
bridge_instance_id      预期接入层实例
remaining_timeout_ms    剩余等待预算，接入层按本地时钟计时
method + payload        受限宿主方法及经过校验的参数
```

握手返回允许方法、CPA 进程身份、接入实例、协议范围、已验证能力及资源预算。后台换代时接入层拒绝旧 owner 的新调用和排队发送；已经进入宿主的调用不因换代被认为结束，也不被再次执行。

`operation_id` 与 `action_id` 分开：同一模型操作包含执行、若干流读取和关闭。模型执行动作禁止自动重试；流读取也不能在回执丢失后盲目重放，否则可能跳过数据。允许重新查询操作的已知状态，不能通过重查状态触发另一次执行。

接入层状态至少区分 queued、entered_host、returned、outcome_unavailable。客户端超时只表示等待结束，不能把 entered_host 自动改成 returned。普通宿主调用与取消/关闭分别保留资源，已阻塞的线程继续占其真实预算。

所有协议对象限制长度、嵌套和缓冲占用，声明长度超过上限立即拒绝。按方法设置不同上限，避免为小额事件分配原生 RPC 最大缓冲。未知方法、超出允许值的 provider、错误账号绑定和跨实例流句柄均拒绝。

## 4. 事件重放与可信状态

事件标识为 `bridge_instance_id + sequence`，每个序号对应不可变事件。后台事务接受事件及推进连续水位，然后确认；接入层按确认结果回收。

额度可以在分配序号之前按账号与字段合并；序号分配后不能原地覆盖事件。重放按序列化结果保持一致，不能重放时重新生成 ReceivedAt 或把旧额度变成新观测。

接入层提供当前最新序号和最早可重放序号。后台水位早于可重放范围时，明确返回 gap，不能只返回剩余事件让后台误认为连续。接入层重启也必然改变实例标识。

无关账号的坏凭据只影响该账号。能够定位账号的活动缺口只标记相关账号；无法定位的缺口标记受影响池的活动可信性。缺口恢复前仍可查看数据和查询额度，依赖占用准确性的自动派发暂停。新一次连接成功或新的一条普通请求本身不足以证明旧的所有请求已结束。

## 5. 数据与事务边界

首个 schema 迁移必须给出字段、索引和唯一约束，不以 JSON 复制旧 `CoreState`。核心键和事务如下：

| 约束/事务 | 需要保证的结果 |
| --- | --- |
| 意图键：账号绑定、规则 ID、周期 ID | 同一周期只抽取一次随机时刻，重复计划不新增意图 |
| 查询认领键：账号绑定、底层额度接口 | 手动、轮询和验证等触发原因共用同一次实际查询，保留请求它的父任务与原因 |
| 账号 guard | 同账号未解决模型操作具有唯一执行授权，不因 worker lease 到期删除 |
| 管理幂等键及请求摘要 | 相同请求返回原任务，不同请求冲突；保留期限在 API 中明确 |
| 容量准入事务 | 重读池目标、有效账号和预约，原子建立本轮预约及操作 |
| 发送授权事务 | 核对 claim、策略修订和取消状态，提交 sending 后才进入宿主 |
| 结果提交事务 | 验证身份和字段栅栏，同时保存账号证据、操作状态与任务结果 |
| 事件接收事务 | 幂等接受事件、更新活动/证据和连续水位 |

保存消息等执行内容只用于明确的模型任务和历史功能，设置长度及保留预算；业务请求正文不进入活动库。任务摘要和账号当前状态可缓存，缓存必须来自已提交版本。

只读任务重启后可以重新执行，但受原任务截止时间和退避约束。prepared 恢复前核对旧执行者与接入层状态；sending 不能自动变回 queued。物理调用槽、worker claim、账号 guard 和容量 hold 使用不同记录及期限。

## 6. 超时、取消与用户可见状态

超时预算分别用于排队、宿主调用等待、上游请求、数据库访问和整个任务；不存在一个超时同时代表所有层都已终止。原生 callback 无法被强杀的事实必须体现在操作状态中。

| 场景 | API 与任务行为 |
| --- | --- |
| 已持久接受任务 | 返回 `202 + job_id`，之后按任务 ID 查询 |
| 参数错误 / 修订冲突 | 返回 400 / 409，任务未接受 |
| 接入层离线 / 本地资源满 | 新管理请求返回明确不可用或繁忙；已持久任务记录 blocked_reason 与下次检查时间 |
| HTTP 响应丢失，是否已接受不明 | 客户端用原幂等键查询或重试，不生成新键再次提交 |
| 队列中取消 | 条件更新为 cancelled，不能再授予发送 |
| 已发送后取消或超时 | 尽力关闭，并显示是否确认结束、是否送达未知；不承诺撤销上游消耗 |
| 数据库失败 | 不报告配置生效或任务接受成功，停止新的模型授权；保留进程内仍未提交的结果并报告故障 |
| 后台离线或页面读取失败 | 页面保留已知结果并标明陈旧，不把读失败解释成任务失败 |

数据库提交回执丢失也可能已经提交，因此变更使用幂等键或前置修订重新核对。前端跟踪任务 ID，而非根据某个按钮是否收到 HTTP 成功来决定上游操作是否完成。

存储故障时未提交结果的内存保留也有上限；达到预算后停止接受更多工作。结果始终无法持久化或进程退出时，后续从已保存 sending 记录恢复未知送达，不能丢弃该记录后恢复发送。

## 7. 发布与交接的执行清单

安装包包含接入层、内嵌前端的后台、协议/数据库元数据及安装器。安装器识别 CPA 服务用户及系统/用户服务方式，生成服务定义和连接路径并检查权限；数据库迁移在后台启动时执行，不提供 V1 数据导入命令。

后续 V2 更新保留数据库中已有的查询和模型规则。新安装的自动查询与自动模型功能默认关闭，安装健康检查不消费模型额度；开启规则必须通过相应业务配置。

首次从 V1 切换不导入旧业务状态，成功后清理 V1 数据；激活失败使用临时一致副本恢复。后续 V2 更新不能清空未知发送记录，回退必须恢复与目标后台匹配的一致数据库。临时副本成功后清除，日后回退须使用升级前另存的备份。

## 8. 编码与验证门槛

组件归属、配置真相、两端点通信、任务幂等、事务状态机和事件序号是持续维护的实现契约。当前 C 接入层使用 json-c 与 libcurl，Go 后台使用 go-sqlite3；固定依赖、资源预算及验证范围见 [架构与构建](architecture.md)，生产负载校准另行记录。

实际 CPA 验证必须记录目标版本/构建、插件 ABI/schema 和部署方式，先验证：

1. 原生 callback 能否在接入层工作线程中调用，以及多个方法并发时的行为。
2. 精确账号执行、provider 与账号代理是否按目标版本工作，流的 read/close/cancel 在并发与超时时是否释放资源。
3. 静态资源和已认证管理路由能否完整转发查询参数、二进制 body、状态码及响应头；动态路由不支持时以固定注册路径加查询参数映射。
4. HTTP、SSE、WebSocket 与故障切换路径的观测字段和完成事件是否符合适配契约。
5. 账号读取是否能取得查询所需的实际凭据，凭据刷新与代理行为是否能被准确分类。

模拟 C 宿主用于故障注入和协议验证；真实 CPA 用于验证宿主契约；真实上游调用单列验证记录。三类结果分开，不将通过模拟测试写成已验证生产可用。

首个端到端验收闭环为：CPA 页面入口 → 后台 API → 持久查询任务 → 接入层获取账号 → 后台额度查询 → 数据库结果 → 页面按 job_id 读取。随后才启用模型副作用和完整自动规则。

## 9. 运行记录与流量证据

schema 12 将安全活动占用和可清理业务记录分开。`traffic_requests` 表示逻辑入站请求，`traffic_attempts` 表示决策或已报告执行，执行次数只统计 `executed=true`。每次物理执行使用宿主执行 UUID 去重，selection ID 只作精确关联键；同 selection 的不同执行仍分别保留。trace 回退仅在实例内唯一时使用，歧义时撤回该回退关联，不能按账号、会话或时间相近推测关联。

决策原因、证据时间和当时优先条件由决策点提交白名单事件；数据库不查询当前额度反推过去原因。规则发送快照和进入 sending 在同一事务提交。API 不读取或返回原始身份、session、API key、凭据、正文；调用方和会话采用数据库盐化摘要，账号 ID 保留原管理身份并由页面展示偏好处理。

流量事件与原生水位在同一事务写入，失败不 ACK；队列溢出、记录容量上限和缺失完成均报告观测缺口。逻辑请求完成不证明所有物理尝试完整，收到 HTTP 响应不证明模型完成，模型完成不证明窗口启动。未知保持未知，不提供强制清除或模型重发入口。

管理 API `GET /api/v2/traffic` 是只读视图；页面刷新、筛选、翻页、读取详情、复制记录 ID 不查询上游或重新执行任务。统计排除插件自身的内部模型调用，逻辑请求/尝试/换号恢复分别计算；已报告 Token 不代表精确账单。聚合与筛选建议须标记裁剪边界，不能把未展示维度默认为无流量。
