# 网页面板

加载包含面板的新插件并重启 CPA 后，在 CPA 插件菜单选择 **Codex Window Refresh**。也可以在同一个 CPA 地址打开：

```text
/v0/resource/plugins/codex-window-refresh/status
```

面板、脚本和样式均随动态库提供，无需安装 Node.js、部署前端服务或允许访问第三方 CDN。传统 CPA 管理模式提供这些资源；已核对的 CPA 宿主在 `home.enabled: true` 时关闭插件资源路由，入口会返回 404。菜单显示还取决于所用管理前端版本。

## 连接与查看

从同源 CPA 管理中心打开时，面板优先读取宿主已保存的管理凭据并自动连接；刷新、切换菜单后重新打开或直接访问同源面板均可复用。兼容 `cli-proxy-auth.state.managementKey` 和旧版 `managementKey`，支持普通 JSON、旧版纯字符串与 `enc::v1::` 混淆格式。已保存的 CPA 地址若指向其他源或其他反向代理前缀，不会复用对应密钥。模块只读取这些已知存储项，不修改 CPA 登录状态。

未保存凭据、浏览器禁止读取存储、跨源部署或认证失败时，输入 **CPA 管理密钥**并连接。这里使用管理 API 的密钥，而不是模型调用 API key。自动连接只先发送一次认证探测，失败不会重试或并行发送其他请求。手动输入的密钥仅保存在当前页面内存，刷新、断开或认证失败后清除；手动断开后不会立即自动重连，重新打开或刷新页面才会再次尝试复用 CPA 凭据。请求始终只发送到当前 CPA 同源的固定管理路径。通过远程地址使用面板时，应沿用 CPA 的 HTTPS 管理入口和管理访问设置。

连接后按用途分为六个页面，顶部始终显示**当前已应用的运行模式**，未保存草稿不会改变这条状态：

- **总览**：账号池状态、手动查询入口及进度，以及被动响应、主动查询和模型唤醒三种数据来源的说明。
- **账号额度**：每个账号的 5 小时及周窗口、剩余额度、数据来源、重置时间与倒计时。唤醒任务默认折叠，展开后查看原因、阻塞状态和暂停操作；“查看执行历史”可直接筛选当前账号。
- **额度查询**：定期查询、五小时到期查询、周到期查询三个独立开关，以及查询间隔和单账号超时；手动查询始终允许。
- **模型唤醒**：自动总开关、默认模型与内容、周唤醒及五小时唤醒各自的开关/随机延迟/专用模型/内容，还有独立的每日时间点与时段规则。
- **计划与历史**：默认展示“账号计划”紧凑表格，每个账号一行，仅显示下一次唤醒时间或暂无时间的原因，按时间排序。历史保留在独立的“执行历史”标签中。账号摘要无需开启完整计划预览，不会额外发起查询或模型请求。
- **诊断与高级**：调度原因、宿主接口能力、手动维护操作和完整 JSON 配置。高级内容默认折叠。

接口能力与额度数据一起在刷新时更新；启动初期显示“未就绪”时，可点击“更新页面数据”，或手动开启自动刷新。“诊断与高级”的“额度查询连接”显示当前查询方式。默认使用宿主账号凭据，不要求后台管理地址或密钥环境变量；只有明确选择兼容管理桥时，才检查这些配置。就绪状态不代表已验证上游连通性或每个账号的凭据。后台凭据过期时，单账号卡片会提示在 CPA 刷新或重新登录。详见[安装说明](install.md#3-配置-cpa)。

宿主模式提供 **检查宿主查询接口**，只验证 HTTP 操作能否创建并取消，显示“尚未检查”“创建已验证”或“创建与取消已验证”及失败状态，不发送上游请求或模型请求。打开页面和刷新快照不会自动执行此检查。实际账号查询失败会显示操作创建、凭据读取、管理接口、上游响应等阶段，以及可用的 HTTP 状态和耗时；后台管理密钥认证失败与上游账号认证失败有不同提示。“最近额度失败”保留运行期间的历史失败，不代表之后的查询仍失败。

近期人数采用宿主认证的 `caller_scope` 去重，共享身份下的多人只计一个。剩余值保留上游单位；没有窗口证据时显示未知，不用本地时间猜测新窗口。面板自动刷新首次默认关闭，在“总览”的 **刷新设置** 中手动勾选 **自动刷新页面（每 5 秒）** 后持续读取本地快照与当前生效配置，不覆盖未保存的规则或 JSON 草稿。此开关立即生效，无需保存策略。“更新页面数据”始终可手动读取快照，不主动调用上游额度查询或模型生成。

当前源码已精简总览：顶部用紧凑状态条显示生效模式，“运行说明”和“额度来源与使用说明”默认折叠。**页面更新于** 只表示刚读取了后台快照；查询入口另列额度观测的新旧范围及观测不完整的账号数。账号额度旁显示相对观测时间，鼠标停留可查看完整时间。最近额度查询有失败时显示提示，失败账号保留之前的观测值；刷新页面不会将旧额度标成刚观测。

账号列表可按名称、五小时或周剩余比例、五小时重置时间、异常与待确认状态排序；比例排序只比较百分比，其他单位与未知值置后。未启动窗口的占位重置时间不参与重置排序。桌面可选择 **紧凑列表**，宽度不超过 940px 时仍显示卡片。排序和布局使用独立浏览器存储键，不保存搜索词或账号 ID，不修改服务器策略，也不发起上游请求。

修改规则后，底部保存栏提供 **配置变更预览**，逐项显示原值与保存后值，涵盖各页面、账号覆盖和高级 JSON 草稿；未应用的 JSON 仍需先应用到草稿。确认保存时也会列出主要差异及模型请求影响。正常情况下对比载入时的服务器规则；文件与运行策略不同时对比当前生效规则。预览不发送写请求，取消保存保留草稿，服务器版本冲突继续由原有版本校验处理。

当前源码增加字段旁校验：数值、时段、延迟、模型、短句池和每日规则出错时给出具体提示。未能解析的输入保留在控件中，不会被页面刷新或应用生成短句覆盖；保存按钮显示 **检查并定位错误**，点击后切换到对应页面、展开所在区域并定位首个错误，不发送保存请求。修正后可继续保存；后端仍执行最终校验，时区库是否包含某个名称也由后端确认。无效输入计入未保存状态，离开和放弃草稿仍有提醒；JSON 修改与未完成表单分别处理。

账号刷新复用现有卡片和按钮，更新变化的文字、数值及可用状态；保持展开状态与可用控件的键盘焦点，账号区域内有焦点或文字选择时保留当前排序，避免正在操作的账号跳位。显式修改排序仍立即生效。正在选中的文字暂缓替换，结束选择后的下一次刷新再更新；倒计时和观测时间也遵守此规则。账号被删除、被主动筛选排除或操作因后台状态变化不可用时，相关内容或焦点仍可能变化。

当前源码会将 **自动刷新页面** 和 **后台标签页继续刷新** 保存到浏览器 `localStorage`，刷新、重新打开页面或重新连接后，在认证连接成功时恢复。断开连接、离开页面和认证失效会立即停止读取，但保留偏好；认证失败不会因为保存了刷新偏好而自动重试。关闭自动刷新会同时关闭并保存后台刷新。偏好按同源和反向代理路径隔离，仅保存这两个布尔选项与格式版本，不保存手动密钥、账号数据或草稿，不修改 CPA 的登录存储。浏览器禁止存储、存储已满或数据损坏时仍可使用面板，可能无法跨页面保留；清理站点数据后恢复首次默认关闭。此行为随 v0.1.0-rc.16 生效，旧版 rc.15 及之前需升级插件后获得。

定期查询、到期查询、模型唤醒、未来计划等开关属于服务器策略，继续通过 **保存规则** 持久化，不以浏览器缓存覆盖服务器状态。网页设计与外部资料参考见 [面板设计参考](panel-design-references.md)。

长期开启时，读取失败会保留现有数据并按 10、20、40、60 秒逐步退避重试，恢复成功后回到 5 秒刷新并隐藏对应错误。浏览器报告离线时暂停，重新联网、返回标签页或窗口获得焦点后按已开启的刷新设置恢复读取；认证失败仍立即断开，不反复尝试密钥。刷新状态显示在总览；自动刷新不会重试保存、查询额度或手动唤醒等写操作。

默认隐藏标签页时暂停自动读取并取消该轮尚未完成的读请求。需要切换标签页后也继续更新时，另行勾选 **后台标签页继续刷新**；取消后台选项、关闭自动刷新或断网时，仅取消自动读取，不影响已经提交的操作。浏览器可能降低后台定时器频率或冻结标签页，电脑休眠也无法继续执行；不能保证后台精确每 5 秒刷新，返回页面后会自动补读。需要浏览器关闭时仍持续查询，应使用插件后台独立的定期查询设置，而不是依赖网页。

状态读取超时或网络错误出现后，下一次完整读取状态快照成功时会自动隐藏对应错误提示；不会清除配置校验、保存冲突或其他操作错误。

额度卡片显示观测来源：正常 HTTP/流式请求响应、WebSocket 请求响应、主动查询或模块唤醒响应。**“正常请求响应”来自用户通过 CPA 发出的请求响应，是被动取得的额度；模块自己的唤醒响应有独立来源。** 后台按请求实际选中的账号与凭据代际更新。完整、有效且均有剩余额度的活跃五小时及周窗口证据会将该账号的下次普通查询推迟到这次观测后一个配置的查询间隔，持续请求可减少重复查询；不是所有响应都包含完整额度。额度事件经过同一协调器落盘并发布，后台网络操作正在进行时可能延后处理，页面轮询间隔不代表端到端最大延迟。

页面右上角的 **从 CPA 刷新** 会立即重新读取 CPA 本地账号清单、禁用和可用状态，再返回完整快照；各标签页均可使用。该操作不连接上游、不查询额度、不发送模型请求，也不通知调度器重新检查规则。已有额度保留原观测时间；账号绑定改变时清除旧绑定的额度证据。刷新不覆盖未保存的配置或 JSON 草稿，失败时保留页面数据。自动刷新和“更新页面数据”仍只读取模块已发布的快照。

对应接口为 CPA 认证管理路径下的 `POST /refresh-accounts`，成功返回与 `GET /snapshot` 相同结构的新快照。此接口不接受上游查询或模型执行参数。

## 只查询额度，不发送模型请求

保持“模型唤醒”的 **启用模型唤醒** 关闭，即可直接手动查询，无需修改或保存开关。需要自动查询时，在“额度查询”手动开启并点击底部的 **保存并应用**：

- **定期查询额度**：默认关闭，开启后调用额度接口，默认间隔 30 秒，可设置 30 秒到 1 小时；关闭后不进行普通定期查询，用户请求的被动额度仍会更新。
- **5 小时额度到期后自动查询 / 周限额到期后自动查询**：默认关闭、分别启用；只对已确认窗口边界到期后查询一次，成功完成标记会持久化，失败退避重试。无需开启定期查询和模型唤醒；未知窗口需先手动查询或由用户请求产生服务端证据，不把占位五小时当成到期计划。
- **单账号查询超时**：默认 15 秒，允许 1 秒到 5 分钟，保存为 `execution.quota_read_timeout`。代理网络较慢时可增加；不改变模型请求超时，CPA 管理接口本身的超时限制仍有效。
- **手动查询始终允许**：可直接在“总览”点击 **立即查询额度**。任务分批查询 CPA 中已绑定的 Codex 账号，包括禁用、暂不可用及只暂停模型唤醒的账号；每轮最多 4 次，显示成功、失败和跳过数量。重复点击合并为同一任务；失败账号在这次手动任务中不自动重试。
- 手动查询不创建唤醒任务，不发送模型请求，不调用“重新检查规则”。自动与手动查询都只访问 `/wham/usage` 额度接口，查询方式未就绪时手动按钮不可用。

在“账号额度”中，每张卡片的 **查询此账号额度** 只查询该账号，更新其 5 小时及周窗口数据，并显示等待、完成或失败状态。账号暂停模型唤醒、CPA 禁用或暂不可用不影响手动只读查询；批量手动查询也包含这些账号。已移除的账号不会发起额度请求，凭据缺失、过期或账号绑定变化时仍会失败。查询不会发送模型请求或自动解除 CPA 的禁用状态。失败不会清空已有额度，也不会自动重试，可再次点击查询。

旧版的“CPA 账号不可用”表示宿主报告 `disabled: true`、`unavailable: true` 或 `status: disabled`，不等同于确定已经耗尽额度。额度耗尽可能使 CPA 暂时标记不可用，但账号禁用、上游错误等也可能造成不可用；需结合额度查询与 CPA 状态判断。旧面板把这些情况统称为“账号已禁用”，并错误地阻止手动查询；上述修正从 v0.1.0-rc.13 起生效。

账号状态现在区分 **CPA 账号已禁用**（`disabled: true` 或 `status: disabled`）、**CPA 账号暂时不可用**（`unavailable: true`）和 **CPA 账号绑定不可用**（无法验证账号身份或凭据绑定）。后台正常运行时约每 30 秒重新读取 CPA 状态，也可点击 **从 CPA 刷新** 立即同步。从 v0.1.0-rc.23 起，单账号、批量和自动额度查询都会同步所查账号的 CPA 状态，包括查询期间发生的禁用、暂不可用或恢复；手动查询结果跟踪会更新卡片，无需开启页面自动刷新。状态以 CPA 实际返回为准，额度恢复不会自行解除 CPA 限制。额度查询失败时仍更新已核实的 CPA 状态，保留原额度和观测时间；账号绑定改变则清除旧凭据证据。

每张账号卡片还提供 **手动唤醒此账号**，点击后必须确认会发送真实模型请求并消耗额度。先填写并保存“模型唤醒”里的模型名称和消息即可，不需要开启自动模型唤醒。此操作只针对所选账号，不启用自动规则；页面中的旧不可用、已启动窗口或退避状态不再禁用按钮。确认后后台先刷新 CPA 状态、查询一次最新额度，再核对账号状态与凭据代际，检查前台请求、退避和重复送达抑制；符合条件才发送，否则在卡片上显示跳过原因。尚有请求待验证、已保存的账号暂停、缺少模型或宿主未就绪仍会阻止提交。暂停或禁用的账号、已经启动的五小时窗口、待验证请求及未就绪的宿主不会发送。手动操作绕过自动规则的人数需求和时段，失败不会自动补发。页面自动刷新关闭时，仍会按任务 ID 自动跟踪执行结果；送达不确定时明确显示，不自动重发。

**查询额度不启动服务端窗口。** 如果额度接口返回 100% 剩余和完整五小时，可能只是未启动窗口的占位值；页面显示“尚未确认窗口启动 · 不倒计时”，不会从查询时间开始减少。手动唤醒会发起实际模型请求，但成功响应本身也不代表倒计时已启动；只有服务端额度证据确认活跃窗口后才显示其实际重置倒计时。不使用本地请求时间加五小时推算。

从 v0.1.0-rc.17 起，将服务端返回的 **大于 0、小于 18000 秒** 的五小时剩余时间识别为窗口已启动，即使已用比例仍为 0、剩余比例仍为 100%。查询、正常请求和唤醒响应均使用此规则；完整 18000 秒仍可能是占位值。服务端同时提供相对倒计时和绝对重置时间时，优先用相对倒计时判断是否已缩短，继续使用服务端重置时间显示倒计时；矛盾字段仍拒绝更新。已发送任务可通过后续一次额度查询完成窗口验证，无需再次发送模型请求。周窗口及双满额提前恢复规则保持原有判断。

v0.1.0-rc.17 修复了原生 Codex 流按行返回、没有行尾换行符时漏读完成事件和额度事件的问题。任务和执行历史也会显示安全的流错误分类，例如“未收到模型完成事件”或“模型流返回失败”；已发送但未验证的请求继续查询窗口证据，不自动补发。排查“请求成功但未倒计时”时，请记录同一次请求的账号、时间、模型、输入 / 输出 token 数以及插件执行历史的结果代码，再对该账号执行一次只读额度查询。计费记录中的“成功”不能替代窗口证据。

在当前 [cpa-key-billing 界面实现](https://github.com/haowang02/cpa-plugin-key-billing/blob/main/internal/plugin/web/events.js) 中，“推理 / 速度”显示推理等级和服务档位，TPS 与延迟另列；这些可选字段为空不能单独判定模型执行失败。具体字段取决于所安装的 CPA、计费插件及模型配置。

单账号和批量查询始终允许，无需开启权限开关，旧配置中的 `quota_query.manual: false` 不再阻止查询。同一时间只运行一个手动任务。相同目标的重复点击会合并，任务结束前其他手动查询按钮暂不可用；自动查询与用户响应被动更新仍由各自机制控制。手动查询、手动唤醒或内容生成期间，即使页面自动刷新关闭，也会按任务 ID 读取进度和结果：开始跟踪后的前 10 秒每 500 毫秒读取一次，之后每秒一次，活动任务结束后停止；不会勾选持续自动刷新或再次提交操作。活动任务读取失败按 1、2、4、8、16、32、60 秒退避；标签页隐藏或断网时暂停，返回或联网后继续，认证失效则断开。浏览器可能降低后台定时器频率，刷新间隔不保证结果显示延迟。额度查询完成时显示后台任务耗时，不包含页面读取与渲染时间。后台重启或保留的任务记录被淘汰会明确提示；最近 64 个任务在后台内存保留，不会因为另一个页面完成了其他账号任务就丢失结果归属。也可随时点击“更新页面数据”。

定期查询与模型唤醒默认关闭，需要用户手动开启并保存；已有配置中显式开启的设置保持不变。只查询额度时保持模型唤醒关闭；若模型唤醒独立开启，其规则仍可能在其他调度周期发送模型请求，发送前核对与已发送操作验证也不受定期查询开关限制。关闭自动查询和模型唤醒后，手动查询和正常请求返回的被动额度仍可更新；已发出的模型请求不会被撤回。

## 修改规则

周限额和五小时额度分别设置自动唤醒开关、到期后的随机延迟上下限、专用模型和发送内容；模型或内容留空时继承默认值。五小时唤醒可限制允许时段，或添加每日规则并选择“固定时间点”“随机时间段”。每日规则有独立总开关，每条规则还可单独开关；按最低就绪容量选择账号，不对所有账号固定发送。自动唤醒总开关仍是最后一道保护；周规则保留不受人数和普通时段限制的原有行为，手动唤醒使用默认模型与内容。

“账号计划”只显示每个账号最早的下一次唤醒。已分配任务显示确定时间，尚未分配的随机延迟显示预计范围；查询任务和未分配账号的每日账号池规则不混入列表。自动唤醒未开启、账号暂停或不可用、请求待验证时显示对应原因；未知窗口或覆盖范围内没有有效安排时显示“暂无可确定时间”。摘要来自当前生效配置，不来自未保存草稿，不新增任务或发送请求。

覆盖天数在“诊断与高级 → 计划预览设置”中修改并保存，默认 7 天，可选 1–30 天。“生成完整计划数据”仅控制详细计划数据，不影响账号摘要；摘要不受详细计划 256 条上限影响。

“模型唤醒”的分组表单编辑总开关、时区、近期活动与账号比例、普通时段、随机延迟和执行模型等规则。“诊断与高级”的 JSON 编辑器提供完整配置，包括每日规则和账号局部覆盖。账号暂停操作修改配置草稿，保存后才生效。

保存前确认变更。保存使用当前策略文件的内容版本进行冲突检查，严格验证后原子替换原文件并热应用规则；保留原文件权限及所有者。保存会重新序列化策略，原 YAML 注释和排版不保留。写入或应用失败时尝试恢复原文件，不报告成功；异常恢复失败会明确提示检查策略文件。

各页面共用同一份草稿，修改后显示底部保存栏，所有配置变更一起保存。切换页面和状态轮询不会覆盖未保存草稿。遇到 `409` 冲突时，先复制需要保留的草稿，再重新读取服务器配置并合并变更；恢复服务器配置会丢弃当前草稿。页面断开或认证失败会清空草稿和账号数据。

策略文件必须为可安全读取的普通 YAML/JSON 文件，路径中的目录及文件不能是符号链接。CPA 运行用户还需要对策略目录具有写入权限，才能执行原子替换；只读部署可查看状态，但不能在网页保存。

**开启规则、取消账号暂停、保存或重新加载启用的策略，都可能让后台调度发送真实模型请求。** 周任务仍按既定规则绕过普通人数和时段限制。重新检查仅通知协调器检查已有规则，不绕过窗口、账号容量或送达抑制。

`重新加载文件` 用于在服务器上手工修改策略后应用文件内容。`重新检查` 用于通知调度器尽快重新检查。两者都需要明确操作；面板不会自动保存、重新加载或重新检查。

## 分区设置与时间轴（v0.1.0-rc.13）

额度查询与模型唤醒分别将 **5 小时** 和 **7 天（周）** 设置为独立卡片。查询卡片中，到期自动查询与定期查询各自设置排除时段和随机延迟；定期查询还有单独参与开关、间隔，仍需公共定期查询总开关开启。两类都取消参与时不定期查询。延迟支持 `0s`、`2m` 等，最短不得大于最长，上限 24 小时；独立间隔填 `0s` 继承公共间隔，否则不能低于公共间隔。

排除时段按规则时区，多个区间用逗号分隔，例如 `22:00-08:00, 12:00-13:00`；留空不排除，`00:00-24:00` 全天排除。随机延迟到期后若仍处于排除时段，则顺延至可查询时间。一次额度接口请求可能同时返回两类额度，因此某类被排除时，另一类允许发起的查询仍可能更新它的额度；排除只限制对应策略主动发起查询。手动查询、被动数据更新、发送前额度核对及发送后验证均不受这些排除设置限制。

账号计划按规则时区显示时间，使用“账号 / 下一次唤醒”两列表格。预计范围仍需满足发送前额度核对、人数容量及其他调度条件，不保证实际执行；修改规则需要保存后才影响摘要。

上述布局和查询策略增强从 v0.1.0-rc.13 起包含在安装包中；升级后需重启 CPA 并刷新网页。

## 随机内容、历史与提前恢复（v0.1.0-rc.14）

默认发送模式为随机短句池，不沿用旧固定消息；固定模式仍可手动选择。每行一条，默认池 1–50 条，每条最多 256 UTF-8 字节，不能为空或重复。五小时与周专用池留空继承默认池；固定模式才使用原固定内容字段。

“用模型批量生成候选短句”需手动选择可用 CPA 账号、模型、5–50 条数量及目标池，明确确认发送请求并消耗额度。生成可在已活跃窗口内进行，仍检查额度、前台请求、账号代际、间隔及待验证操作。结果先展示在预览中，可编辑，再点击“替换对应短句池草稿”，最后单独保存。生成失败、关闭页面或送达不确定均不自动补发；账号绑定不确定时不会换账号调用。

五小时到期自动查询增加近期用户活动开关，默认关闭、默认回溯 30 分钟（可设 1m–7d）；按整个账号池真实用户活动判断，进行中的请求也算。唤醒、生成或手动查询不算用户活动。手动、定期、周到期查询与发送核对不受此条件限制。

详细计划数据仍保留规则与额度证据来源，账号摘要不展开这些诊断信息。执行历史不依赖计划生成开关，在“计划与历史”切换到 **执行历史** 后读取；保留 30 天、最多一万条，分页默认 50 条，支持上一页和下一页。快捷筛选包括 **今天、最近 7 天、仅失败、清空筛选**：日期以浏览器本地日历计算，“最近 7 天”包含今天和前 6 天，结束时间留空以包含后续新记录；记录时间仍按规则时区展示。可与账号、类型和结果筛选组合，手工时间需带时区并满足开始不晚于结束。读取失败保留上次结果并提示，只有历史子视图可见且页面刷新开启或正在跟踪任务时才随快照更新历史。记录实际发送模型、短句、操作标识和固定错误码；不记录凭据或用户正文。已发送待验证、已验证和送达不确定分别显示，验证不会另建唤醒记录。

提前恢复仅在同一可靠响应中，两类额度精确为 100%，原来两类都有已确认消耗且倒计时尚未结束、权限明确允许时生效。一次观测即可清理两类旧倒计时、旧基线及未发送的到期意图，显示窗口未启动，记录原边界和来源。不会依据满额响应启动新计时、不会新增提前恢复唤醒；已发送的验证和抑制标记保留。单类满额、显示四舍五入到 100%、陈旧或矛盾响应不视为提前恢复。

新增已认证的 `POST /prompt-generation` 接受 `request_id`、`account_id`、`model`、`count`、`target`（`default/five_hour/weekly`）以及可选 `provider`（省略或 `codex` 使用 Codex，`antigravity` 使用反重力），返回 202 排队状态；状态及候选在 `GET /summary` 的 `scheduler.prompt_generation` 中。请求标识避免重复调用，生成失败或不确定后须用户明确再操作；同一标识不自动重试。

当前源码支持使用 CPA 中的反重力账号及其可用模型生成候选短句。先点击右上角“从 CPA 刷新”同步账号，在“模型唤醒 → 用模型批量生成候选短句”选择带“反重力”前缀的账号，填写该账号在 CPA 中可用的模型名，再确认生成。反重力模型名必须显式填写，不继承 Codex 默认模型；CPA 负责模型路由和凭据使用，无需额外输入密钥。禁用、暂时不可用或身份无法确认的账号不会作为可用选项。

反重力仅用于手动短句生成，不进入 Codex 五小时/周额度、账号容量或自动唤醒池，不调用 Codex 额度查询。生成使用反重力自身额度，仍遵守账号禁用、身份绑定、已知前台请求互斥和发送间隔，并在调用前持久化送达记录；失败或送达不确定不会自动重试。生成结果沿用预览、应用到目标短句池草稿、保存配置的流程。`GET /snapshot` 的 `generation_accounts` 提供独立的生成账号目录，不包含凭据、邮箱或项目 ID；历史中的 `provider` 标识反重力任务。

`GET /history` 接受 `account_id`、`kind`（`query/wake/generation/reset`）、`status`、含时区 RFC3339 的 `from/until`、`cursor` 和 `limit`（1–100，默认 50）；返回最新优先的 `entries` 和 `next_cursor`。保留规则是固定的 30 天与一万条。接口及记录仅在管理认证后可读。

无需旧数据迁移步骤，不导入旧消息或补造历史；历史从新版实际执行开始产生。安装保留已有安全状态。旧版严格解码不能读取新增状态字段；如需回退，先停服务并恢复升级前匹配的备份。此增强从 v0.1.0-rc.14 起包含在安装包中，升级后重启 CPA 并刷新网页。

## API 与更新

原 `GET /config` 继续返回当前运行配置；`GET /config-editor` 返回磁盘策略与 `revision`，`POST /config` 接收 `{ "config": { ... }, "revision": "..." }`。`POST /quota-query` 无请求体或传 `{}` 时查询全部已绑定账号（包括禁用或暂不可用账号）；传 `{ "account_id": "账号 ID" }` 时只查询该账号，进度中的 `account_id` 标识所选目标。未知账号返回 404，不同目标的手动任务正在执行时返回 409。数据和修改接口均位于 CPA 已认证的 `/v0/management/codex-window-refresh/` 下；公开资源只包含静态页面资产。

网页面板从 `v0.1.0-rc.2` 开始包含在发布安装包中。安装脚本默认选择最新已发布版本，重新下载并运行安装脚本、重启 CPA 后即可使用。提交到 `main` 的源代码不会自动替换已有 Release 资产；也可从源码构建 `.so` 后按安装说明替换并重启 CPA。

## 开发验证

`make panel-check` 使用 Node.js 18+ 的内置测试器验证前端逻辑。安装 Node.js 22+ 与 Chromium 后，还可运行真实浏览器验证：

```sh
CHROME_BIN=/usr/bin/chromium node scripts/panel-browser-check.mjs
```

浏览器测试仅连接临时的本地模拟 API，验证手动登录、CPA 凭据格式复用、刷新与重新打开、菜单 iframe、失效凭据单次探测与手动回退、账号文本安全、配置保存与冲突、运行模式、跨页面草稿与保存栏、详情展开保持、键盘导航、五个页面的移动布局和认证失效后的数据清理，并保存截图。它不会连接真实 CPA 或账号。发布流程要求 Chromium 检查和两种架构的构建检查均通过后才发布。

从 v0.1.0-rc.24 起，已知五小时窗口到期后，新查询返回满额且允许请求时，可按已有到期计划自动唤醒，仍检查人数、时段、CPA 可用性及发送抑制。“尚未确认窗口启动 · 不倒计时”继续表示没有实际启动证据，不等于禁止执行已有到期计划。没有历史到期依据时不会仅凭满额建立自动任务。

“下一次唤醒”对已分配任务保留原定时间；到期未执行时显示等待原因，例如人数比例容量已满足、额度证据未知或不在允许时段。已知的下次核对时间单独显示，核对时间变化不会改变原定随机延迟。
