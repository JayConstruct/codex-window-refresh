# 持久化存储

`internal/storage.FileStore` 实现 `core.Store`，使用标准库，没有新增 module 依赖。第一版支持 Linux。其他平台的 `Open` 返回 unsupported，不能回退成没有进程锁的实现。

```go
store, err := storage.Open("/private/plugin-state")
if err != nil {
    return err
}
defer store.Close()

state, err := store.Load(ctx)
if err != nil {
    return err
}
// 修改 state；网络发送前必须提交 dispatch_intent。
revision, err := store.Commit(ctx, state.Revision, state)
```

## 文件与权限

专用目录由当前用户拥有，权限必须为 `0700`；新建目录使用该权限。既有目录权限不符合时拒绝打开，不自动修改用户已有目录。目录下使用：

| 文件 | 用途 | 权限 |
| --- | --- | --- |
| `.lock` | 生命周期内持有的非阻塞 `flock(LOCK_EX)` | `0600` |
| `state.json` | 唯一有效的完整状态快照 | `0600` |
| `.state-*.tmp` | 单次提交的临时快照 | `0600` |

状态和锁文件必须由当前用户拥有且是普通文件；拒绝符号链接。存储只编码 `core.CoreState`，包含账号稳定标识、凭据代次标识、窗口证据、任务、预约和不可逆活动身份等调度数据。凭据代次标识不是凭据内容；不要将原始 token、API key 或上游响应正文放入 core 字符串字段。文件权限保护本机访问，存储不提供加密。

schema 1 的文件形态为：

```json
{"schema":1,"state":{"Revision":1,"Accounts":{},"Activity":{}}}
```

核心字段名称由 Go 类型决定。解码拒绝未知字段、未知 schema、缺失/null state、损坏 JSON 和尾随内容。没有 `state.json` 的首次打开返回 revision 0；存在但不可读或损坏的文件绝不当作新状态重置。当前限制快照大小为 128 MiB，避免无限读取损坏的文件。

## 提交与恢复

`Commit(ctx, expectedRevision, next)` 在进程内互斥锁下重新读取当前状态，核对修订号，写入 `expectedRevision + 1`。`next.Revision` 不决定修订号，也不会修改调用者传入对象。修订号冲突返回可用 `errors.Is(err, storage.ErrRevisionConflict)` 判断的错误，不覆盖文件。达到 `uint64` 上限时拒绝提交。

提交按以下顺序执行：

1. 创建独立临时文件并写入完整 JSON。
2. `fsync` 临时文件并关闭。
3. 再次检查当前状态、目录及锁文件，随后检查取消信号。
4. 原子 `rename` 为 `state.json`。
5. `fsync` 状态目录。
6. 返回新修订号。

成功结果意味着文件和目录同步均成功。调度器必须在成功提交发送意图后才能进行网络发送。若进程在发送意图提交后退出，重开读取到的 `dispatch_intent`、OperationID 和发送抑制标记保留，恢复逻辑应先查询证据，而非重发。

`rename` 前失败不会报告提交成功，并清理本次创建的临时文件。`rename` 后目录同步失败意味着提交结果不确定：返回错误并封锁本实例的后续操作，调用者停止发送，关闭并重开后核对磁盘状态。取消信号在替换前检查；替换一旦完成，优先完成同步，即使 context 随后取消也可能返回成功。

加载始终从文件重新解码，因此返回的 map、slice、指针与此前状态独立。Accounts、Activity、Requests 的 nil map 初始化为空 map。JSON 解码保留 core 所有持久化字段的完整内容。

## 锁与外部变更

锁是合作式的，同一目录的第二个 `Open`（含另一进程）立即失败。正常 Close 或进程退出会释放锁；`.lock` 文件保留，不能删除再创建来“解锁”。

每次加载和提交核对已见状态内容的 SHA-256、是否存在、目录 inode 和锁 inode。外部修改、删除、新建状态或替换锁文件会使已打开实例报错并封锁，不能通过再次 Load 接受改动。维护时应停插件、保留备份，再重开；没有自动合并外部修改的流程。

flock 无法阻止不遵守锁协议的外部程序在检查之后写入文件。部署时应仅允许本实例写入专用目录；多台机器/网络文件系统的锁与断电持久性不在本实现保证范围内。文件原子替换与 fsync 的持久性依赖宿主文件系统。

Open 只读取 `state.json`，不尝试提升临时快照。崩溃遗留 `.state-*.tmp` 不改变已提交版本，也不会自动删除；这样不会误删外部用户文件。可在停插件并确认没有运行实例后人工清理。

## 任务历史与生成结果（v0.1.0-rc.14）

状态快照新增 `History`（30 天、最多一万条）、`GenerationJob`、每个实际发送任务的模型／内容及提前恢复标记。任务发送前提交对应记录，送达不确定不会自动重试；后续验证更新同条唤醒记录。历史只包含插件任务短句、规则和额度来源，不记录凭据或用户正文。

新增字段缺失时可读取 rc.13 快照，无需独立迁移程序；不补造旧历史，也不删除账号与送达抑制状态。旧版会因未知字段拒绝新快照，如需回退须停服务并恢复升级前对应备份，不手工删除送达抑制字段。固定状态 schema 仍为 1，保持原安全校验和损坏时停止行为。

## 验证范围

存储测试覆盖：CAS 冲突与并发竞争、深拷贝、重开恢复、子进程提交后直接退出、跨进程排他锁、外部修改/删除/新增/锁替换、坏 schema/JSON 不重置、临时快照忽略、context 取消、无效 JSON 数值、只读/不安全权限、符号链接以及 Close 后拒绝操作。目录 fsync 故障注入验证结果不确定时停止操作、重开核对已写入的发送意图。测试中的进程退出验证进程崩溃恢复，不能模拟真实主机断电；断电持久性依赖上述 fsync 协议及文件系统。
