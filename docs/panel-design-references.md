### CPA 版本边界

核对时，官方管理中心 main 的 README 已要求 CPA v8，并说明管理中心使用 `/v8/management`，插件资源与自定义扩展保留后端声明的路径。本项目当前管理接口仍是 `/v0/management/codex-window-refresh`。官方 Management API 页面也仍有 v0 示例，因此不能仅凭在线文档把本插件所有路径替换为 v8；升级适配应单独核对真实宿主、插件资源路由和认证存储格式。

## 2. 哪些开关应当记在浏览器

| 设置 | 持久化位置 | 生效方式 |
| --- | --- | --- |
| 自动刷新页面、后台标签页继续刷新 | 当前浏览器 localStorage | 点击立即生效；连接成功后恢复；首次默认关闭 |
| 定期额度查询、到期查询、模型唤醒、未来计划 | 服务器规则文件 | 修改草稿后点击“保存规则”；再次进入读取服务器值 |
| 手动输入的管理密钥、账号额度数据、未保存草稿 | 不新增浏览器持久化 | 手动密钥仅在会话内使用；额度重新读取；未保存草稿保留离开提醒 |

“未来计划”的自动预览开关虽然不会直接发送上游请求，但它是服务器规划设置，已经属于规则契约，不应另存一个浏览器值与服务器争夺状态。

## 3. 本次实现的浏览器偏好契约

当前面板在 `internal/plugin/web/panel.js` 中管理偏好：

- 键名：`codex-window-refresh:panel-preferences:v1:` 加当前同源管理 API 路径；例如根路径部署以 `/v0/management/codex-window-refresh` 结尾。协议、域名和端口由浏览器同源机制隔离，反向代理前缀由键名隔离。
- 值：`{"version":1,"autoRefresh":true,"backgroundRefresh":false}`。只接受版本 1 和布尔字段，不解析字符串真假值。
- 自动刷新开启时读取本地快照；恢复偏好不调用额度查询、模型唤醒或规则保存接口。
- 关闭自动刷新会同时关闭后台刷新并保存。断开、离页和认证失败只停止当前读取，不清除用户偏好；重新认证成功后再恢复。
- 本地存储不可用或写入失败时保留当前会话选项；数据缺失、损坏或格式版本不支持时默认关闭。
- 同一浏览器的多个页面各自运行刷新循环，未增加跨标签页实时联动；新打开的页面读取最近保存值。
- 清理站点数据会清除这些偏好。它不跨设备同步，也不保证隐私模式关闭后的保留。

本次变更随 v0.1.0-rc.16 安装包生效；旧插件需更新后才能获得此行为。rc.11 等历史发布说明中“重新打开后关闭”的表述仍描述当时版本。

## 4. 已落实的首轮页面优化与后续方向

当前源码已落实以下改进，仍需构建并部署包含修改的插件：

- 总览的运行模式改为紧凑状态条；刷新选项、运行说明和额度来源说明可折叠。
- 保存栏增加逐项原值与新值预览，确认框列出主要差异；原有草稿保护、确认和版本冲突处理继续生效。
- 页面读取时间与额度观测时间分别显示，额度相对时间随本地时钟更新；额度查询失败保留旧值并提示最近失败。
- 账号支持名称、两类剩余比例、五小时重置时间和异常优先排序；新增桌面紧凑列表，手机继续卡片布局。仅比较百分比数据，未知值与其他单位后置；未启动窗口的占位重置时间不参与排序。
- 排序和布局通过 `codex-window-refresh:account-view:v1:` 加 API 路径单独保存，值为版本、排序方式和布局。访问异常回退默认，搜索词和账号 ID 不持久化；与刷新偏好、CPA 登录和服务器规则相互独立。

后续一轮已实现字段旁校验和首个错误定位，保留无效输入及跨页面草稿；账号刷新复用节点并保护焦点、选中文字和操作中的排序；“计划与历史”提供独立子视图、日期及失败快捷筛选、双向翻页和账号历史入口。服务器仍执行最终配置校验，历史读取不提交操作。当前修改仍需构建并部署。

后续仍可评估：

1. 将已有保存预览按功能分组，支持更方便地核对长文本和多账号覆盖。
2. 统一状态用语，清楚区分“读取页面快照”“查询上游额度”“发送模型请求”；加载、空数据和错误状态给出可执行的下一步。
3. 用一致的字号、间距、对齐与颜色表达额度和任务优先级，减少重复说明与装饰，让账号列表和时间轴更容易扫描。
4. 后续如增加主题、列表密度或展示偏好，可沿用独立存储与异常回退；需同步更新格式版本、文档和恢复测试。

以上后续方向尚未全部实现；已经完成的范围以本节和面板说明为准。

## 5. 验证入口

`make panel-check` 包含首次默认、刷新偏好重开与重连、关闭后保留、认证失败停止、存储异常和代理路径隔离，以及原有草稿、快照顺序与任务跟踪检查。

具备 Chromium 与 Node.js 22 时，可运行 `node scripts/panel-browser-check.mjs`，使用本机假服务验证浏览器 reload 后的恢复、宿主登录键不变和移动端布局；不访问真实 CPA 或账号。使用 `CHROME_BIN` 可指定浏览器路径。
