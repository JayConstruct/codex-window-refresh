# v0.1.0-rc.12 测试版

细分自动查询与模型唤醒设置，并增加未来查询、唤醒计划预览。

## 本次变化

- 独立的“5 小时额度到期后自动查询”“周限额到期后自动查询”开关，默认关闭；无需开启定期查询或模型唤醒。仅针对服务端已确认窗口边界，到期后查询一次，两种窗口同时到期合并为一次账号查询。成功接受对应窗口字段后持久化完成标记；失败、部分响应按已有间隔及退避重试，重启不重复已完成边界。
- 周限额和五小时自动唤醒分别配置开关、随机延迟上下限、专用模型与发送内容。任一模型或消息留空时继承默认值；五小时到期及每日时间规则使用五小时配置，周规则使用周配置，手动唤醒仍使用默认模型与消息。
- 五小时唤醒允许时段与每日时间点/随机时段分开设置。每日规则增加独立总开关，并提供固定时间点或随机时间段控件；仍按最低就绪容量选账号，不对所有账号固定发送。关闭不删除规则，不撤回已发出的请求。自动唤醒总开关及窗口、前台活动和重复送达限制保持有效；周任务保留原有的人数与普通时段豁免。
- 新增“未来计划”页面。计划生成默认关闭，手动开启并保存后自动预览未来 1–30 天的查询与唤醒；最多显示最早 256 项，周期查询使用循环条目。显示预计随机范围与已分配的实际时间，不重抽随机值、不增加意图，不因此开启或执行其他请求。
- 未知窗口及完整五小时占位额度不推算后续周期。未来计划依据已知服务端窗口、有效时区、已有任务、账号覆盖和退避生成，实际执行仍需额度、人数容量与安全检查；预览不承诺未来一定执行。
- 兼容旧配置：新增到期查询和计划生成开关默认 false，专用模型与消息为空时继承原设置；每日规则独立总开关继承 true，不意外关闭原有每日规则。原有开关、模型、窗口状态及已分配随机时间保留。

## 安装或升级

已有 CPA 的 Debian 12/13 服务器执行：

```sh
curl -fSL https://raw.githubusercontent.com/JayConstruct/codex-window-refresh/main/scripts/install.sh -o /tmp/codex-window-refresh-install.sh && sudo bash /tmp/codex-window-refresh-install.sh --version v0.1.0-rc.12
```

升级保留现有配置与状态，默认重启已核实的 CPA systemd 服务，可能短暂中断请求；使用 `--no-restart` 推迟重启。root 会话可省略 sudo；命令要求已有 curl，缺失时先安装 ca-certificates 和 curl。CPA 路径或服务无法唯一识别时，沿用 `--cpa-dir`、`--service`、`--user-service`、`--user` 等参数。Docker 部署请按安装指南替换容器内插件。

重启 CPA 后刷新管理网页：在“额度查询”分别选择定期、五小时到期或周到期查询；在“模型唤醒”配置周/五小时模型、内容、延迟及每日时间规则；在“未来计划”开启生成并选择天数。所有草稿需“保存并应用”后生效，页面自动刷新仍默认关闭，可手动读取最新计划。

## 验证与边界

本地全量 Go 测试、race、vet、31 项前端逻辑测试、78 项安装器测试及原生 ABI 加载检查通过。新增回归覆盖独立开关、每窗口查询去重和重启、部分响应重试、专用模型与消息、每日规则停用、只读计划生成、已分配随机时间不变、有界排序、固定时间点与时区/DST。发布流程要求 Chromium 浏览器检查与 Linux amd64、arm64 构建、安装器和原生加载检查全部通过后，才上传安装包和 SHA256SUMS。

仍要求 CPA ABI 1 / RPC schema 6。尚未在真实 CPA 宿主或生产账号上联调；同步 C 回调完全不返回时不能强行中断，前台请求与后台发送的竞态边界保持不变。计划只是预览，不推测新的服务端窗口，不自行刷新 OAuth，不绕过发送前安全检查。
