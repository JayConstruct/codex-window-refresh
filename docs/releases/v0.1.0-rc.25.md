# v0.1.0-rc.25 测试版

修复真实 Linux 文件监听下的热重载安装兼容问题。

## 原因与修复

安装器此前通过临时文件和 rename 替换 CPA 主配置。核对的 CPA 实现监听配置文件本身，仅由 Write、Create 或 Rename 事件触发重载；Linux 原子替换产生旧文件的 Chmod、Remove 及监听移除事件，导致 CPA 不读取新的版本选择和确认标记。版本文件可能一直保留旧版 running 和空 reload_token，安装器则报告无法确认升级或恢复。先前假宿主的配置轮询没有覆盖此行为。

热重载现在采用与 CPA 自身配置保存一致的原文件写入方式，保留 inode、拥有者和权限。写前备份并核对预期内容，拒绝符号链接、硬链接及并发修改；完整写入、截短残留并 fsync，写入异常时尝试通过同一文件恢复原内容。其余安装文件继续原子写入。回滚主配置同样保留监听；不覆盖正在映射的动态库，不增加管理 key 或 HTTP 确认。

失败提示增加失败步骤、最后一次有效观测的版本和阶段、是否收到本次配置确认及实例是否变化，不输出确认标记或密钥。诊断仍无法证明升级成功时继续保留文件和备份，不自动重启。

## 已遇到旧版失败的部署

保留安装备份和 runtime-version.json，先核对安装记录、实际运行版本和主配置的版本选择。若宿主监听已因旧脚本替换文件而丢失，新脚本无法在进程外重新安装这份监听；需要恢复宿主配置监听，无法在线恢复时需用户显式选择一次 CPA 重启。不要仅修改版本文件、删除已映射的库或反复执行旧脚本。恢复监听后，一键脚本继续默认热重载。

## 验证

新增真实 Linux inotify 回归：三次配置确认均须从文件监听事件触发，回滚后仍能收到后续修改；覆盖短写后失败恢复、较短配置截断、inode、权限和拥有者保留、并发修改及链接拒绝。继续检查原有版本确认、未知回滚保留与新实例二次确认，以及 Go、竞态、原生加载、安装器、前端、Chromium 和双架构构建。
