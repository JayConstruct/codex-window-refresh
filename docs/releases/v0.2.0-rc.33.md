# v0.2.0-rc.33 明确显示五小时窗口未启动

五小时额度剩余 100%，且上游返回完整的 `reset_after_seconds=18000` 时，账号状态和五小时额度栏明确显示“窗口未启动”，归入有余额的可用账号。按查询时保存的原始返回值判断，几分钟后查看或刷新页面时钟也不会将其显示为已启动倒计时。

未返回相对秒数时，使用该窗口原始观测时间和重置时间做整秒比较；显式相对秒数优先于采样和取整后的绝对时间。短于五小时的倒计时、已有用量或已确认活动的窗口不会被这条规则判为未启动。周额度耗尽、禁用、受限和实际到期查询等状态继续保留。窗口显示与活动窗口容量、后台查询及唤醒准入各自使用原有口径。

后台和客户端安装包为 **v0.2.0-rc.33**，接入层保持 **v0.2.0-rc.32**，数据库保持 **schema 12**。从 rc.32 更新时，安装器确认接入层文件完全一致后可省略 `--restart`，仅更新并重启后台；完成后强制刷新网页。从 rc.31 或更早版本升级仍须显式 `--restart`，同时加载 rc.32 接入层。已有账号、规则、任务和防重记录保留，客户端启动器内容沿用 rc.31。

验证覆盖网页测试和 Chromium：两分钟前查询的完整五小时窗口保持未启动，状态和额度单元格一致，时钟更新不改成倒计时；同时验证原有到期查询倒计时、手动卡片数量查询及桌面/移动端布局。发布流程执行 amd64/arm64 完整构建、竞态检查、浏览器回归和公开安装包回读验证。
