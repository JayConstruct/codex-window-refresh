# v0.1.0-rc.17 测试版

修复少量请求已有输出、五小时倒计时已缩短，但面板仍显示“尚未确认窗口启动”的问题，并完善模型流解析与唤醒错误诊断。

## 本次变化

- 五小时窗口的服务端剩余时间严格在 `0 < remaining < 18000` 秒时，即使 `used_percent=0`、剩余额度仍显示 100%，也识别为活跃窗口。查询、正常请求和插件唤醒响应共用此规则；倒计时使用服务端重置时间，不以本地发送时间加五小时推算。
- 优先使用服务端显式相对倒计时判断窗口是否已缩短；只有绝对截止时间时使用整 Unix 秒差，避免小数秒把完整五小时误判为缩短。完整 18000 秒仍保留未确认，非法或矛盾字段仍拒绝更新；周窗口与双满额提前恢复继续沿用既有规则。
- 修复 CPA 原生 Codex 流逐行返回、没有行尾换行符时，完成事件、文本和额度事件被拼接丢失的问题；保留分片 SSE、多行数据、CRLF 和原始 JSON 的支持。模型流仍需完成事件才能判定执行完成，HTTP 200 或流结束本身不替代完成事件。
- 同一请求的响应头和后续部分额度事件分别保留原始时间及消息边界，避免周额度覆盖五小时证据，也避免把分开的消息拼成同一响应的双窗口重置证明。流读取失败、中断、超大帧或错误事件出现后仍保留已收到的额度证据；仅保留有界数量的原始消息。
- 唤醒任务与执行历史保留并显示安全的错误分类，区分未收到完成事件、读取失败和模型失败；不记录上游原始错误或凭据。后续额度证据确认启动后，任务显示完成并清除当前错误提示；历史仍保留当次执行诊断。

## 安装或升级

已有 CPA 的 Debian 12/13 服务器可指定版本升级：

```sh
curl -fSL https://raw.githubusercontent.com/JayConstruct/codex-window-refresh/main/scripts/install.sh -o /tmp/codex-window-refresh-install.sh && sudo bash /tmp/codex-window-refresh-install.sh --version v0.1.0-rc.17
```

升级保留已有策略、模型、窗口和发送抑制状态，无需清空状态或迁移历史。安装器默认重启已核实的 CPA systemd 服务，可能短暂中断请求；使用 `--no-restart` 可稍后手动重启。路径或服务不明确时沿用 `--cpa-dir`、`--service`、`--user-service`、`--user` 等参数；Docker 按安装指南替换插件。

替换插件并重启 CPA 后刷新面板，对受影响账号执行一次 **查询此账号额度**。如果服务端返回缩短的五小时倒计时，即使已用比例仍为零，也可确认活跃窗口，并在适用时完成已有唤醒任务的验证，无需再次点击手动唤醒。

## 验证与边界

新增回归覆盖零用量的 1 秒、17999 秒、18000 秒边界，绝对重置时间的小数秒采样，绝对与相对时间共存，原生无换行模型流，以及手动唤醒发送前、发送响应和后续查询三条窗口识别路径。保留完整五小时占位、周额度、双窗口提前恢复与送达不确定的重复发送抑制验证。

发布流程要求 Linux amd64、arm64 各自通过完整 Go 测试、竞态检测、vet、原生 ABI 加载、安装器、发布一致性及前端检查，并通过 Chromium 浏览器回归后才发布两种安装包与 SHA256SUMS。前端逻辑测试共 93 项。

仍要求 CPA ABI 1 / RPC schema 6；自动化验证使用模拟宿主与本机浏览器服务，尚未连接真实 CPA 宿主或生产账号验证。升级不会主动重发旧的送达不确定请求；任务仍需服务端额度证据确认窗口。
