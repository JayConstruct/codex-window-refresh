# v0.2.0-rc.8 模型唤醒与可编辑生成提示词

- 接通 Codex 手动单账号唤醒、五小时/周重置自动唤醒及每日容量准备。自动总开关和各项自动规则默认关闭，需核对实际模型、提示词及规则后明确开启；反重力仍仅支持短句候选生成，不支持唤醒。
- 新增独立的唤醒规则编辑、差异预览、版本冲突保护和消费确认。运行总览的自动唤醒开关可直接保存，不夹带编辑器其他草稿；网页关闭后后台继续执行已开启规则。
- 日常观测到实际窗口重置后，结合账号、业务需求、容量与时段判断；满足条件则进入唤醒。启动时按账号随机分散并持久保存期限，重启不重新抽签。周规则独立于普通容量和允许时段，每日规则按配置时区准备目标容量，不按固定数量无条件发送。
- 唤醒使用已保存的默认或五小时/周覆盖模型及提示词，支持从已保存短句池随机选句。发送前核实账号绑定、宿主能力与实例、新鲜额度字段、活动占用、容量预约及共享模型预算；不解除禁用、不猜模型、不切换账号或提供方。
- 唤醒采用持久计划与幂等任务，模型返回成功先进入 `verifying`；后续只读额度或真实业务证据确认活动窗口后才显示 `completed/window_verified`。发送结果未知时不自动重发，重启、修改规则、换请求标识或候选生成均不能绕过账号保护。
- 原生接入层对新模型请求执行串行预算保护：旧流未关闭或仍在清理时不接收下一次调用。仅明确尚未进入宿主调用的预算繁忙可重新等待；已经发送的未知结果不按此路径重试。接入层私有预算字段不透传给 CPA 宿主。
- 候选生成提示词现在可独立编辑、恢复默认并保存，与唤醒提示词分开。本次生成固定使用提交时的草稿快照；后续修改不影响已有任务，同一幂等标识更改提示词会冲突。固定数量、JSON 数组及短句长度约束继续保留。
- 网页新增唤醒计划与历史、预检/发送/验证/未知阶段及阻塞原因，总览异常和最近事件包含真实唤醒状态。页面读取、同步和普通模型配置保存不发送模型请求；额度查询本身仍只读，但显式开启的自动唤醒规则可因新额度观测独立创建模型任务。

## 升级

本版须同时更新后台与原生接入层，并显式 `--restart` 重启 CPA，会短暂中断服务。数据库从已发布 rc.7 的 schema 6（或源码 schema 7）迁移到 schema 8，保留查询设置、模型配置、候选结果、幂等记录及未知发送保护。升级前另存一致备份；降级必须停服务并恢复升级前备份，不能只替换旧二进制。

```sh
curl -fSL https://raw.githubusercontent.com/JayConstruct/codex-window-refresh/main/scripts/install-v2.sh -o /tmp/cwr-v2-install.sh
sudo bash /tmp/cwr-v2-install.sh --version v0.2.0-rc.8 --restart
```

用户级 systemd 服务继续支持 `--user-service --user 用户名 --service 服务名`。更新后强制刷新网页，先保持自动规则关闭，核对实际模型、时区和允许时段，再按需确认手动唤醒测试账号；满足准入并实际发送时会消耗模型额度。观察模型完成与窗口验证后，再按需开启自动规则。已在源码版保存开启的规则会保留，更新不会擅自关闭。

## 验证与边界

本地通过完整 Go 测试、竞态检查及 vet、131 项前端检查、32 项原生桥接测试、116 项安装脚本测试及桌面/移动端 Chromium 回归。测试覆盖真实接入层预检与精确账号发送流程、模拟模型响应、只读窗口验证、未知结果恢复、串行预算及临时安装回滚；未调用真实账号模型，不声称已完成真实 CPA 生产账号联调。

活动观测和发送前复核不能提供 CPA 前台请求与后台调用之间的原子互斥。自动模型目录选择、其他提供方唤醒及分布式派发仍未接入；不要用模型试发替代只读目录或额度核对。
