# v0.2.0-rc.19 CPA 插件拦截请求体内存优化

## 本次改动

- 原生桥接层按宿主支持的最高版本协商 RPC Schema：CPA Schema 7 使用 7，旧版 CPA Schema 6 仍继续使用 6。
- 对 Schema 7 宿主，RequestInterceptor 显式声明 `request_interceptor_omit_body_before` 与 `request_interceptor_omit_body_after`，减少长 Codex 会话请求体不必要的克隆、Base64 序列化及插件边界传输。
- 保留鉴权前后所需的 RequestID、Metadata、caller_scope、选中账户、请求完成和配额统计事件处理；未删除流式响应初始化、WebSocket 额度观察或后台管理功能。
- 新增 Schema 6/7 注册及无正文拦截回归测试，确认旧版兼容性。

## 性能与兼容性

这项优化仅在 CPA 核心支持 Schema 7 时生效；旧版 CPA 使用原有 Schema 6 行为。它针对请求拦截时的 Body 传输，不代表已优化每个 SSE chunk 的 RPC。实际内存改善需要在生产负载中复测。

后台与原生桥接层均更新到 v0.2.0-rc.19。现有 SQLite 数据与配置保持不变，升级前建议备份数据库。

## 升级

```sh
curl -fSL -H 'Cache-Control: no-cache' https://raw.githubusercontent.com/JayConstruct/codex-window-refresh/main/scripts/install-v2.sh -o /tmp/cwr-v2-install.sh
sudo bash /tmp/cwr-v2-install.sh --version v0.2.0-rc.19 --restart
```

原生桥接层二进制有变化，需要重启 CPA 以加载新版。建议先升级 CPA 到支持 Schema 7 的版本，检查插件注册和管理页面再恢复任务。
