# v0.1.0-rc.21 测试版

热重载改为本机版本文件确认，无需 CPA 管理 key 或密钥文件。

## 变化

- 插件自动在 `state_dir/runtime-version.json` 写入实际版本、运行阶段、进程身份、实例 ID 和实际加载库路径。文件以 `0600` 原子替换，仅在生命周期及配置确认时更新，不包含账号凭据或管理密钥。
- 安装器移除热重载的管理 HTTP 查询和密钥读取，使用本机配置标记与版本文件往返确认：先确认旧版读到配置，新版接管后再次确认同一实例读到新标记，避免把残留文件或刚开始注册的实例视为成功。
- 核对 CPA PID、进程启动时间、boot ID、运行程序、文件拥有者、权限及安装路径；拒绝残留文件、符号链接、异常文件、超大或损坏内容。进程退出或重启后旧文件不再有效。
- 暂停、关闭及后台异常退出更新阶段；旧实例释放状态锁后不能覆盖新实例的文件。加载失败时继续支持 CPA 恢复旧实例，确认恢复后固定旧版；结果未知时保留现场和备份，不擅自重启。
- 旧的 `/lifecycle` 管理接口仅保留诊断用途，不再是热重载依赖。热重载本地确认协议为 2，业务策略及现有持久化状态保持兼容。

## 安装或升级

rc.20 及更早版本不会生成版本文件，首次升级到 rc.21 需普通安装并重启一次：

```sh
curl -fSL https://raw.githubusercontent.com/JayConstruct/codex-window-refresh/main/scripts/install.sh -o /tmp/codex-window-refresh-install.sh && sudo bash /tmp/codex-window-refresh-install.sh --version v0.1.0-rc.21
```

此后升级到兼容新版，使用同一最新安装命令加 `--hot-reload`，沿用原来的路径、用户和服务参数，不需 `--key-file` 或管理地址。版本文件由插件创建，不要手动填写。详细操作与首次升级限制见 [安装说明](../legacy/v1/install.md#热重载升级)。

## 验证与边界

回归覆盖实际状态锁交接、配置标记确认、旧实例不能覆盖新版、后台异常阶段、残留进程身份、错误路径或权限、符号链接、FIFO、损坏及超大文件，以及全程不读取管理密钥、不访问管理 HTTP、不执行 systemd 重启。原生假宿主继续验证两个动态库的切换、失败恢复及重新打开。发布要求 amd64、arm64、竞态检测、原生加载、安装器、前端和 Chromium 回归通过。

模拟验证尚未代替真实 CPA 和生产账号联调。要求安装器与 CPA 可见同一文件和 PID 命名空间及 `/proc`；Docker 应在容器内执行，主配置和插件目录需支持原子文件替换。旧 Go 映射仍驻留到 CPA 进程退出，切换期间可能有短暂观测交接窗口。
