# v0.1.0-rc.26 测试版

修复五小时窗口尚未确认启动、已有五小时到期任务却只显示未来周唤醒计划的情况。

## 变化

- 核实的周与五小时联合重置可以清除旧五小时基线，同时保留尚未由成熟周任务接替的五小时待执行意图。计划现在直接读取这些保留任务，继续显示原定时间和等待原因，不再因为基线为空漏掉任务。
- 对仍在等待的五小时到期任务，发送检查可以使用任务保存的原到期边界核对新查询的满额占位值。原有随机延迟、任务身份及结果保留，不重抽、不新造一个周期。
- 新的非空基线继续优先；已确认未来窗口、已完成或被替代的任务、未到随机时间的任务、没有五小时历史的首次满额观测、过期或不完整额度都不能因此绕过限制。账号状态、人数、时段、前台请求、送达未知及重启抑制继续有效。
- “尚未确认窗口启动”只描述缺少实际启动证据。它本身不能证明账号已经重置；如果从未记录五小时窗口且没有待执行五小时任务，周计划可能仍是唯一已知计划。可显式手动唤醒建立实际窗口，不把查询占位值当成启动证据。

## 升级与验证

沿用修复后的安装脚本默认热重载，保留已有策略、窗口及任务。已因旧脚本丢失 CPA 配置监听的部署仍须先恢复宿主监听，详见 [rc.25 说明](v0.1.0-rc.25.md)。

新增回归从真实联合重置状态迁移复现基线清空后的任务保留，覆盖未来周计划不遮住旧五小时任务、先查询再执行、原定时间与证据来源保留，以及首次满额观测不创造历史任务。继续执行 Go、竞态、原生热重载、安装器、前端、Chromium 和双架构发布检查。尚未在真实 CPA 生产账号上联调。
