# v0.2.0-rc.39 每个 Codex 窗口独立选择官方或 CPA

客户端在每次交互启动、新建或恢复会话时显示连接菜单：`1` 官方 ChatGPT 登录，`2` CPA。终端通过 `cwr-codex` 启动，Codeman 继续使用已有 CWR 启动入口，在对应终端窗口内选择。安装器同时将 `CPA_API_KEY` 名称加入 Codeman 的 tmux／Docker 环境转发列表，保留原列表，不保存密钥值；安装或更新后重启 Codeman 服务以加载注册表，此后各窗口选择连接无需重启服务。

支持同时运行不同目录的多个 Codex 窗口，各自选择官方或 CPA。菜单选择只作用于当前子进程，不保存为全局模式、不修改 Codex 配置，也不改变运行中的其他窗口。CPA 的项目头按各窗口最终工作目录生成。模型、推理强度、动画、提示词和恢复会话参数继续透传；取消、EOF 或 Ctrl+C 退出选择时不会启动 Codex。

显式 `--mode official`、`--mode cpa` 或 `--mode auto` 跳过菜单。`--set-mode` 继续保存默认模式：交互菜单可回车采用已保存的官方或 CPA 默认项，非交互启动直接使用保存值。未保存模式时非交互仍默认 `auto`，交互菜单须明确选择。管道、`exec`、`review`、`login`、帮助、版本和协议服务等命令不显示菜单、不消费输入来选择连接。

CPA 仍需先在 Codex 配置中定义提供商，并通过 `--trust-cpa-url` 登记完整 API 地址。CPA 模式优先采用匹配的当前提供商；全局默认官方等其他目标时，可选唯一匹配的已登记 CPA 定义，或按 `--provider`／保存的提供商 ID 约束选择。多个候选、地址不匹配、profile 不受支持、组织策略控制提供商或原生路由参数冲突时明确报错，不猜测目标或失败后改走其他渠道。`auto` 保持只检测当前生效路由、不切换提供商。

官方继续使用 Codex 管理的 ChatGPT 登录，子进程移除 API Key 和地址环境覆盖，保留代理和证书设置。并行使用时，CPA 应配置提供商独立 `env_key` 及 `requires_openai_auth = false`，避免与官方登录共用认证缓存；配置示例见[使用说明](../user/account-scheduling.md#每个窗口单独选择连接)。菜单不会登录、复制凭据或发送模型请求。已有客户端设置与目录映射保留；只向已登记 CPA 添加项目头的保护继续生效。

后台与客户端安装包为 **v0.2.0-rc.39**，原生接入层保持 **v0.2.0-rc.36**，数据库保持 **schema 12**。本次功能仅需更新客户端，不要求升级服务端。服务端若从 rc.35 或更早版本升级，仍须显式 `--restart`，同时加载后台和配套接入层。

回归使用真实 PTY 和模拟 Codex 验证并行窗口、各自路由、项目头、环境隔离、默认项、取消及输入保留，并通过本机实际 Codeman 注册表和命令渲染器验证新建／恢复参数。真实 Codex 仅执行配置读取及本地模拟 HTTP 请求，不登录、不访问真实账号或上游模型。
