# v0.1.0-rc.1 测试版

CLIProxyAPI Codex 账号窗口唤醒插件的首个测试发布。

## 下载与安装

- `linux_amd64`：`uname -m` 返回 `x86_64`。
- `linux_arm64`：`uname -m` 返回 `aarch64`。
- 两种安装包在 Debian 12 bookworm 环境原生构建，面向同架构 Debian 12/13 的 glibc 环境；Alpine/musl 不适用。
- 解压前用 `SHA256SUMS` 校验下载；安装说明见包内 `INSTALL.md`，或仓库 [V1 安装指南](../legacy/v1/install.md)。
- 包内包含插件 `.so`、配置检查工具、默认关闭自动请求的示例策略、构建信息和许可说明。

## 已实现

- 本地窗口到期后持久化随机延迟，精确绑定目标账号请求。
- 周任务优先，夜间执行且不受人数比例限制。
- 普通任务按近期认证身份和比例补足容量，合并同账号的成熟任务，并保留错过时间后的补发。
- 有效五小时窗口内禁止发送；请求后以实际额度证据验证新窗口。
- 持久化发送意图；重启、超时及未知送达结果保留重复发送抑制。
- 查询预算、失败退避、超时，以及不等待网络的管理状态与容量汇总。

## 验证与边界

发布流程要求两种架构各自通过测试、race、vet、原生 ABI 加载和构建检查，然后生成安装包与 SHA-256 校验和。

当前仅通过本地与假宿主测试，尚未验证真实 CPA 宿主和真实账号。要求原生插件 ABI 1、RPC schema 6；接口核对基于官方提交 `3de4e248f6bb12fc7dfafb183404f3b248578922`。旧版本或其他 fork 的兼容性未验证。

实际后台并发为 1。零用量和未来 reset 时间不能单独证明窗口未激活，因此缺少正向窗口证据的账号可能等待。宿主未提供前台请求与插件发送之间的原子互斥，最终观测与发送之间仍有竞态。

首次安装保持策略 `enabled: false`，确认管理摘要、账号窗口及额度查询正常后，再在少量账号上开启规则。未核实的窗口不会通过推算 `now + 5h` 被认定为已刷新。
