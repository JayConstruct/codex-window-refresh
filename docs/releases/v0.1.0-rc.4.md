# v0.1.0-rc.4 测试版

接入 CPA 正常请求返回的 Codex 额度信息，减少重复主动查询，面板更快显示最新额度。

## 本次变化

- 普通 HTTP 与流式请求通过 `X-Codex-*` 响应头更新额度；WebSocket 通过上游 `codex.rate_limits` 事件更新，也接收错误事件附带的额度头。
- 按请求选中的账号及已核对的凭据代际绑定观测，重试换号和已发现的账号替换不会把旧响应套用到其他账号；未知绑定、缺少额度和畸形信息忽略，正常响应原样保留。
- 流式响应头只在 header-init 读取一次，不用后续 chunk 的旧响应头刷新倒计时。回调不查询网络，不保留提示词、响应正文、凭据或流历史；请求绑定有容量与时间上限。
- 完整有效的活跃五小时及周窗口证据、两者均有剩余额度、已知允许权限且没有待验证操作时，将普通查询推迟到此次额度观测后至少 30 秒；持续请求可减少重复查询。部分/未知/到期证据、初次初始化、空闲回退、唤醒前核对和未完成操作验证仍使用主动查询。
- 新响应额度不会被较早开始的查询覆盖，被新证据取代的查询不误报失败。
- 面板每 5 秒读取本地快照，额度卡片标明正常请求响应、WebSocket 请求响应、主动查询或模块唤醒响应来源。保留 rc.3 的 CPA 登录状态复用。

## 升级

重新下载安装脚本，沿用原 CPA 路径、服务和用户参数，指定 `--version v0.1.0-rc.4`，安装后重启 CPA，再刷新管理中心。

```sh
curl -fL https://raw.githubusercontent.com/JayConstruct/codex-window-refresh/main/scripts/install.py \
  -o /tmp/codex-window-refresh-install.py
sudo python3 /tmp/codex-window-refresh-install.py --cpa-dir /root/cliproxyapi --version v0.1.0-rc.4
```

提供 Linux `amd64`、`arm64` 安装包和 `SHA256SUMS`，支持 Debian 12/13；升级保留已有策略、私有管理密钥环境文件和窗口状态。

## 验证与边界

回归覆盖 HTTP/流式/WebSocket 额度解析、异步完成通知、账号及代际绑定、重试换号、旧查询冲突、部分字段保留、流式头去重、有界绑定与并发、正常响应无修改、无需额度桥的被动状态更新、减少重复轮询与空闲回退。原生假宿主加载覆盖新增三个 RPC，Chromium 检查额度来源与 5 秒快照刷新；发布流程要求两种架构的 Go/race/vet、安装器、前端和原生加载检查全部通过。

仍要求 CPA 原生 ABI 1 / RPC schema 6，接口核对基于官方提交 `3de4e248f6bb12fc7dfafb183404f3b248578922`；尚未在真实 CPA 宿主或生产账号上联调。并非每个响应都有完整额度，已失效绑定回退主动查询。后台网络操作可能延后队列处理，5 秒是页面轮询间隔，并非端到端最大延迟。自动唤醒仍依赖管理额度桥，实际生成并发仍为 1，前台与后台之间仍缺少宿主原子互斥。
