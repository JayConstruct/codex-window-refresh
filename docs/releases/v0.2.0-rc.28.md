# v0.2.0-rc.28 Codex 调度台与运行记录

按确认稿重构全部 V2 页面，显示名称更新为“Codex 调度台”。顶部横向导航统一为总览、账号、自动化、项目调度、运行记录及设置；总览展示可用窗口、等待重置、后台任务和待办，账号页增加详情与筛选，自动化和项目匹配采用对应的编辑布局。兼容手机、CPA 暖灰/纯白/深色主题，保留草稿、版本冲突及结果未知时的只读核实。

运行记录新增用户请求、插件调用和分流分析，并保留任务记录。请求详情展示实际执行账号、当时分流原因、逐次上游尝试及已报告用量；支持项目、调用方、会话和账号维度分析及下钻。逻辑请求、上游尝试和换号恢复分别统计，插件自身调用与正常业务分开。未采集的数据保持未知，不按时间猜测归属，也不根据 HTTP 429 直接判定额度耗尽。

接入层使用有界异步事件缓冲记录业务决策及执行，调用方和会话使用每数据库盐化摘要；记录不保存用户请求正文或管理密钥。插件调用依据已保存的任务和响应证据展示，旧数据不能还原完整网络日志。记录受采集缺口、保留期及数量上限约束，详细边界见[面板指南](../user/panel.md)。

账号可用筛选与总览容量共享证据规则，容量分母采用已启用账号，额度排序在全池执行后分页。修复项目账号勾选被表单重绘清除、批量查询重复点击、迟到任务详情覆盖当前选择等交互问题；同值轮询保留已展开内容和输入焦点。

文档按使用、开发、研究及 V1 历史资料重组，网页测试统一移到 `tests/web/v1` 和 `tests/web/v2`，打包文档链接保持包内名称或固定到发布提交。设计稿与实现截图见 [UI 重构说明](../development/ui-redesign.md)。

## 升级要求

后台、客户端及原生接入层均为 **v0.2.0-rc.28**，数据库升级为 **schema 12**。从 rc.27 或更早版本升级，必须同时更新后台与接入层，并显式 `--restart` 重启 CPA，加载新页面资源和运行记录路由；不能只替换后台。客户端启动行为沿用 rc.27，仍记住用户选择的提供商 ID。

升级保留 schema 1–11 的账号、任务、规则及发送防重记录，已有自动化设置继续按已保存规则执行。升级前另存一致数据库备份；schema 12 不能交给旧后台直接打开，回退必须停止后台并恢复与目标版本匹配的备份，不能只换旧二进制。

```sh
curl -fSL https://raw.githubusercontent.com/JayConstruct/codex-window-refresh/main/scripts/install-v2.sh -o /tmp/cwr-v2-install.sh
sudo bash /tmp/cwr-v2-install.sh --version v0.2.0-rc.28 --restart
```

## 验证范围

本地验证包含 Go 测试、vet、竞态、安装器与文档测试、网页测试、原生假宿主联调及完整 Chromium 回归。29 张桌面/手机/主题截图检查无页面溢出或控制台错误；只读预览未创建任务或修改账号状态。发布流程另在 amd64/arm64 构建、校验并回读公开安装包。上述验证使用临时数据和模拟宿主，未进行真实账号查询、模型发送或重置卡兑换验收。
