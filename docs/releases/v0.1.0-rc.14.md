# v0.1.0-rc.14 测试版

新增随机唤醒内容、模型批量生成、近期用户活动查询条件、计划来源与执行历史，完善双额度提前恢复识别。

## 本次变化

- 所有账号默认使用随机短句池，不导入旧默认或专用消息。内置五条简短唤醒语，支持默认池、五小时／周专用池；专用池留空继承默认池，每条最多 256 UTF-8 字节、最多 50 条。可手动切换固定内容模式。每次实际发送只选一次，发送前持久化选中的模型与内容，刷新和重启不会重新选择或重发。
- 管理面板支持选择 CPA 账号、模型、目标池和数量，明确确认消耗额度后调用一次模型生成 5–50 条候选。结果先预览、可编辑，再应用到草稿并单独保存；不自动保存、不自动补充、不自动重试送达不确定的请求。生成可能启动所选账号窗口，可在已有活跃窗口内执行，仍受账号、额度、前台请求、间隔和重复发送保护。
- 五小时到期自动查询可要求整个账号池近期有真实用户活动，独立条件默认关闭，回溯默认 30 分钟、可设 1m–7d。进行中的用户请求也算活动，插件唤醒、内容生成和手动查询不计用户使用。不满足时保留未完成边界；定期、周到期、手动查询及发送核对不受影响。
- 时间轴上的每条计划展示触发规则和额度证据来源、观测时间及原重置边界；合并查询保留全部触发来源。执行历史记录查询、唤醒、内容生成与提前恢复事件，支持账号、类型、结果、时间筛选和分页，持久化保留 30 天、最多一万条。
- 历史展示实际发送模型、短句、操作标识和固定错误码，区分成功、失败、跳过、已发送待验证、已验证及送达不确定。后续验证更新同条唤醒记录，不记录用户请求正文、凭据或远程错误正文。
- 新鲜同一响应中两类额度精确恢复为 100%，此前均有已确认消耗且旧倒计时尚未结束、权限明确允许时，一次观测即可清理旧倒计时、基线和未发送的旧周期任务。显示窗口未启动，记录原边界和来源，不推算新计时、不新增提前恢复唤醒；已发送操作的验证与抑制保留。首次满额、单类恢复、四舍五入满额、陈旧或矛盾响应不使用此判定。

## 安装或升级

已有 CPA 的 Debian 12/13 服务器执行：

```sh
curl -fSL https://raw.githubusercontent.com/JayConstruct/codex-window-refresh/main/scripts/install.sh -o /tmp/codex-window-refresh-install.sh && sudo bash /tmp/codex-window-refresh-install.sh --version v0.1.0-rc.14
```

无需旧数据迁移步骤，不导入旧消息或补造历史；历史从新版本实际执行开始记录。安装保留现有配置与安全状态，不清空账号绑定或送达抑制。默认重启已核实的 CPA systemd 服务，可能短暂中断请求；使用 `--no-restart` 推迟重启。root 会话可省略 sudo，路径和服务不明确时沿用原安装参数。Docker 按安装指南替换插件。

重启 CPA 后刷新网页。随机池编辑后需保存；批量生成需先确认模型调用，候选应用到草稿后仍需另行保存。“未来计划”页面可读取执行历史，不必开启计划生成。自动查询、自动唤醒和页面自动刷新仍需用户开启。

新版可以读取缺少新增字段的 rc.13 状态，但旧版不能读取新增字段后的状态；如需回退，须停服务并恢复升级前匹配的备份，不删除发送抑制标记。

## 验证与边界

本地全量 Go 测试、race、vet、45 项前端逻辑测试、78 项安装器测试、原生 ABI 加载和构建通过。回归覆盖随机内容持久化、生成确认与重启抑制、真实用户活动门槛、查询条件独立性、同响应双满额与陈旧／部分证据、历史过滤／分页／限额和来源文本安全。发布流程要求 Chromium 检查以及 Linux amd64、arm64 构建、安装器测试和原生加载全部通过后，才上传安装包和 SHA256SUMS。

仍要求 CPA ABI 1 / RPC schema 6，尚未在真实 CPA 宿主或生产账号上联调。模型生成会消耗所选账号额度；网页不能保证浏览器冻结或电脑休眠时刷新，宿主同步 C 回调完全不返回时无法强行中断。提前恢复依据一次可靠双满额观测判定，不能宣称消除全部上游短暂异常；插件不自行刷新 OAuth，未知送达仍禁止自动重发。
