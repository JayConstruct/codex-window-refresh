# v0.2.0-rc.18 唤醒旧任务结束与按需重新调度

## 唤醒任务

- 修复五小时和每日唤醒任务在目标容量已满足后长期停留在“排队中”或“执行中”的问题。发送前检查和最终发送授权均将这些未发送任务结束为“已跳过”，保留“目标容量已满足”原因；已有旧任务在后续调度检查时按同样规则处理。
- 同一重置周期之后出现容量缺口时，可以重新创建已明确未发送的容量跳过任务。容量仍满足时不反复创建记录，旧记录保持终态；新的五小时周期继续正常调度。
- 额度预检被活动状态、执行资源等准入条件暂缓时回到排队状态，避免把等待误显示为持续执行。每轮调度共用一次容量读取，发送前仍重新核对。
- 已发送、窗口核实中及结果未知的任务不进入上述重新调度路径，继续保留原有发送防重和只读核实保护。

## 一并发布的页面改动

- 包含此前本地 rc.17 的账号启停拨动开关和“手动禁用”状态。主页面立即查询、立即唤醒及启停直接操作，不显示确认弹窗；保留实际账号、绑定、重复提交及结果未知保护。
- 自动唤醒额度提示首次确认后按浏览器及 CPA 地址记忆，后续开关、编辑和刷新不重复提示。模型页独立手动唤醒表单与候选生成确认保持原流程。

## 升级

后台为 **0.2.0-rc.18**，原生接入层沿用 **0.2.0-rc.14**，数据库保持 **schema 9**，ABI 1、RPC schema 6、协议版本 1 不变。保留已有账号、配置、任务和未知发送保护，不自动开启或关闭规则。

从 rc.14–rc.17 更新且安装器核实接入层文件一致时可仅重启后台；首次切换、从 rc.13 或更早版本更新，或接入层文件变化时须添加 `--restart`。升级前保留停机或 SQLite 在线一致备份。

```sh
curl -fSL -H 'Cache-Control: no-cache' https://raw.githubusercontent.com/JayConstruct/codex-window-refresh/main/scripts/install-v2.sh -o /tmp/cwr-v2-install.sh
sudo bash /tmp/cwr-v2-install.sh --version v0.2.0-rc.18
```

保留原部署所需的 CPA 路径及系统/用户服务参数，需要重启 CPA 时在末尾添加 `--restart`。更新后重新打开或强制刷新网页以加载页面改动。
