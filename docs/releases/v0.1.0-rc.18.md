# v0.1.0-rc.18 测试版

修复手动唤醒按钮被旧账号状态锁定、无法通过重新查询判断是否需要唤醒的问题，并细分 CPA 账号状态。

## 本次变化

- 页面与管理 API 不再因为缓存的账号不可用状态拒绝手动唤醒；页面中的旧窗口和退避状态也不再禁用按钮。确认后刷新账号清单、查询所选账号一次最新额度，再核对 CPA 状态和凭据绑定，符合条件才发送，否则显示跳过原因。
- 查询此账号额度完成后，手动唤醒按钮可继续发起重新核对；查询成功不会自行解除 CPA 的禁用或暂时不可用标记。模型未保存、账号已暂停、宿主未就绪或已有请求待验证时仍不能提交。
- 区分“CPA 账号已禁用”（disabled 或 status: disabled）、“CPA 账号暂时不可用”（unavailable）与“CPA 账号绑定不可用”。正常运行时后台约每 30 秒检查账号清单；页面自动刷新默认关闭，可手动更新页面或开启自动刷新。
- 保留窗口、额度、前台活动、退避、发送间隔、凭据变更及重复送达保护。额度查询后再次刷新账号状态期间出现前台活动时停止发送；CPA 仍报告不可用时明确显示原因，不把额度恢复等同于账号恢复可用。

## 安装或升级

已有 CPA 的 Debian 12/13 服务器可指定版本升级：

```sh
curl -fSL https://raw.githubusercontent.com/JayConstruct/codex-window-refresh/main/scripts/install.sh -o /tmp/codex-window-refresh-install.sh && sudo bash /tmp/codex-window-refresh-install.sh --version v0.1.0-rc.18
```

升级保留已有策略、模型、窗口和发送抑制状态，无需清空状态。安装器默认重启已核实的 CPA systemd 服务，可能短暂中断请求；使用 `--no-restart` 可稍后手动重启。Docker 按安装指南替换插件。新增状态字段写入后，回退旧版本需停服务并恢复升级前对应备份。

替换插件并重启 CPA 后刷新管理面板。需要手动唤醒时点击账号卡片上的按钮并确认，等待额度核对及唤醒或跳过结果；无需开启自动唤醒。

## 验证与边界

回归覆盖缓存不可用账号的排队、额度查询后按钮可用、状态恢复后发送、仍不可用或明确禁用时跳过，以及额度耗尽、活跃窗口、退避、凭据更换、状态读取失败和核对期间前台活动等路径。

发布流程要求 Linux amd64、arm64 各自通过完整 Go 测试、竞态检测、vet、原生 ABI 加载、安装器及前端检查，并通过 Chromium 浏览器回归后才发布两种安装包与 SHA256SUMS。

仍要求 CPA ABI 1 / RPC schema 6；自动化验证使用模拟宿主，尚未连接真实 CPA 宿主或生产账号验证。已发送但结果不确定的请求不会自动重发。
