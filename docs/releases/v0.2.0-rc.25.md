# v0.2.0-rc.25 项目目录账号匹配与提供商启用条件

“账号调度与重置卡”新增可视化项目匹配：列出项目标识、运行 Codex 的电脑上的绝对目录及首选账号，支持新增、编辑、删除项目，导入现有 projects.json，从 CPA 已同步的 Codex 账号清单点选账号。账号清单支持独立搜索、状态筛选及分页，并显示已有五小时、周额度和观测时间；不会受主账号表筛选影响，不查询上游、不执行模型。

同一项目可登记多个目录，支持 POSIX、Windows 盘符和 UNC 绝对路径。导入时保留同名项目的首选账号，重复目录和跨项目冲突在导入与保存前校验；文件读取失败、其他编辑或重新选择文件时，旧读取不会覆盖新草稿。输入换行、焦点和选区在账号刷新时保留。保存后可下载启动器使用的目录映射；未保存、冲突或保存结果待核实时不可导出新映射。每个项目最多 16 个目录、1000 个首选账号，总计最多 128 个项目，完整设置最多 256 KB。目录是用户登记或导入的客户端路径，后台不扫描客户端文件系统；发布给调度器的快照仅含项目和首选账号，不含目录。

客户端 cwr-codex.py 的 --provider 改为用户填写的项目调度启用条件，默认 cpa。只有配置文件及所选 profile 中的当前提供商与该 ID 完全一致时，才读取目录映射并添加 X-CWR-Project；启动器不再注入 model_provider 覆盖。修改配置切换到其他提供商后，重新运行同一条启动命令会直接使用该提供商，跳过目录映射，目录文件缺失也不影响其他提供商启动。显式命令行切换提供商、OSS 模式及远程 app-server 同样跳过注入，客户端判断不改变后台总开关。

启动器按当前独立 profile 文件约定处理 --profile/-p，并保留原始 Codex 参数；旧版隐式 profile、配置无效或读取失败时不猜测提供商，交给 Codex 原有流程处理。读取 TOML 需 Python 3.11+，Python 3.10 可安装 tomli；诊断不回显配置内容。共享目录映射中的其他操作系统绝对路径会跳过，本机目录仍在客户端解析符号链接并取最长路径匹配。

后台与原生接入层均为 **rc.25**。接入层将调度设置 POST 上限从 6 KB 提升至 256 KB，与后台保持一致，避免项目清单增加后保存失败。升级必须同时更新并显式 **--restart**，客户端也需替换包内启动器；更新后强制刷新网页。数据库保持 **schema 10**，从 rc.21–rc.24 升级无需迁移，保留现有规则、额度及发送防重记录。旧项目账号配置无需填写目录，也可继续使用显式项目标识。保存的首选关系仍遵循 CPA 候选过滤、优先级与会话绑定，不改变账号授权范围。

验证覆盖 Go 全量测试、vet、竞态检查，模拟宿主大于 6 KB 的调度设置保存与重启回读，目录持久化及调度快照不包含目录，启动器提供商切换与 profile 条件，以及浏览器导入、点选、保存回读、下载、搜索分页、隐私与焦点。真实 Chromium 覆盖 320/390/768/1586 像素布局、完整面板和自动刷新回归。发布流水线在 amd64/arm64 构建、测试，并下载公开安装包验证校验和、安装更新及回滚；使用模拟宿主与临时数据，未操作真实账号或重置卡。

使用步骤见[项目与账号](../account-scheduling.md#项目与账号)，升级见[V2 安装与更新](../backend-v2-install.md)。
