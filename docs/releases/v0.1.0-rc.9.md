# v0.1.0-rc.9 测试版

默认通过 CPA 宿主账号凭据查询额度，不再要求额外的管理地址或管理密钥环境变量。管理接口桥接保留为可选兼容方式。

## 本次变化

- `quota_transport` 默认 `host`。每次查询重新读取账号凭据、核对账号身份与代际，再 GET 上游 wham/usage；不发送模型请求，也不调用登录、凭据保存或 refresh-token 接口。
- 无账号专用代理时使用 CPA HTTP 回调及其全局代理。支持账号级 HTTP、HTTPS、SOCKS5、SOCKS5H 和显式 direct/none 代理；宿主 HTTP 操作超时会发出取消回调。
- 已过期、缺少凭据、代理无效及上游失败有固定诊断；单账号查询卡片显示失败原因，已有额度保留。
- 默认安装和升级不读取或写入管理密钥文件；升级将安装器自身的 systemd override 改为无需环境文件依赖，旧密钥文件与业务策略保留。
- 明确设置 `quota_transport: management` 或安装参数 `--quota-transport management` 时继续使用原管理桥。旧管理地址和变量名可以保留，宿主模式下不使用它们。

## 使用和升级

安装脚本指定 `--version v0.1.0-rc.9 --quota-transport host`，沿用原 CPA 路径、服务与用户参数。root 用户服务示例：

```sh
python3 /tmp/codex-window-refresh-install.py --cpa-dir /root/cliproxyapi --user-service --service cliproxyapi.service --user root --version v0.1.0-rc.9 --quota-transport host --yes --restart
```

先重新下载主分支的安装脚本；安装包内也包含对应新版脚本。旧策略存在时沿用模型，不再要求后台管理密钥。首次安装若省略模型而要自动识别，可临时提供网页登录密钥；明确 `--model` 时宿主模式无需密钥。使用旧版安装包仍自动保留管理桥兼容，显式 host 要求本版或更新版本。

更新后重启 CPA、刷新管理面板，在“诊断与高级 → 额度查询连接”确认宿主模式，然后使用自动、批量或单账号查询。单账号按钮仍受“允许手动查询”控制。模型唤醒是独立开关。

## 验证与边界

通过 token 轮换、账号更换阻止、过期和缺失凭据、401 分类、代理选择、响应大小限制、取消宿主操作及错误脱敏测试。原生 C 假宿主在无管理桥配置下成功执行自动与单账号额度查询，模型请求数为 0。安装测试覆盖无需密钥的默认安装、旧环境文件保留、用户服务升级和管理桥兼容；浏览器验证查询、诊断与布局。

CPA 仍是 OAuth 续期的唯一所有者，插件不自行旋转 refresh token。`host.auth.get` 读取物理凭据文件，可能暂时落后于宿主内存；遇到过期凭据应等待 CPA 刷新、重新登录，或选择管理桥。就绪状态不代表已验证每个账号的凭据或网络。仍要求 CPA ABI 1 / RPC schema 6；尚未在真实 CPA 宿主或生产账号上联调。提供 Linux amd64、arm64 安装包及 SHA256SUMS。
