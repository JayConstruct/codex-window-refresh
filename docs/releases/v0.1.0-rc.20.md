# v0.1.0-rc.20 测试版

支持插件热重载：新版使用独立版本文件接管，插件升级不必每次重启 CPA。

## 变化

- 区分可恢复的 `plugin.quiesce` 和最终 `plugin.shutdown`；排空旧任务、提交待处理观测、释放状态锁后才允许新实例接管。新版注册失败时，支持 CPA 重新配置旧实例恢复。
- 保留同一 CPA 进程中的已知前台请求占用；真实进程重启清理旧占用。已派发或送达未知的模型请求不自动重发。修复暂停取消与本地状态提交并发时可能误将健康存储标为失败的问题。
- Linux 原生映射使用 `RTLD_NODELETE` 保留 Go 代码到进程退出；最终关闭排空后清理 service，允许宿主重新打开已关闭的映射。每个热重载版本使用独立 `.so` 路径，不能覆盖或反复复用仍被宿主保留的映射。
- 增加认证 `/lifecycle`，提供运行版本、热重载协议、运行阶段及实例 ID，不连接上游。
- 安装器增加 `--hot-reload`：核对安装记录、包协议、当前运行实例和配置，固定旧版后放入独立新版，再切换选择；确认目标版本和新实例运行才报告成功。安装时固定版本选择，避开宿主对 rc 版本字符串排序的差异。
- 注册失败且已确认旧版恢复时固定旧版，保留失败版本路径和备份。结果未知时保留现场并报告，不擅自重启 CPA。支持版本化安装的普通重启升级和卸载，兼容 CPA 下次启动清理历史文件。

## 升级

**从 rc.19 或更早版本升级到 rc.20 仍须普通安装并重启一次**。旧版本缺少可恢复暂停及映射保护，无法安全补做此次热重载：

```sh
curl -fSL https://raw.githubusercontent.com/JayConstruct/codex-window-refresh/main/scripts/install.sh -o /tmp/codex-window-refresh-install.sh && sudo bash /tmp/codex-window-refresh-install.sh --version v0.1.0-rc.20
```

此后升级到支持相同协议的更新版本，使用同一入口加 `--hot-reload --key-file /root/cpa-management-key`，沿用原来的路径、用户和服务参数。密钥文件须由 root 拥有、权限 `0600`；临时密钥只用于本地管理状态核对，不持久化。`--hot-reload` 不重启服务，不能和 `--restart` 同用。默认普通安装流程仍会重启。

需 CPA ABI 1 / RPC schema 6、版本文件热切换与失败恢复，以及 v0 管理插件接口。详见 [安装说明](../install.md#热重载升级)。保留已有业务策略、模型和状态。切换后自动任务仍遵循原有配置；安装器不测试模型或查询上游额度。

## 验证与边界

本地原生假宿主覆盖两个独立 Go 动态库的加载、重复暂停、状态锁互斥和交接、失败恢复、关闭与重新打开，以及宿主缓冲区释放；无模型请求。Go 回归覆盖交接队列提交、前台占用恢复、进程重启区别、未知送达抑制、暂停超时和取消期间的提交。安装器回归覆盖新版确认、失败恢复、状态未知、旧版拒绝、并发配置保护和不执行 systemd 操作。

发布仍要求 amd64、arm64 的 Go 测试、竞态检测、vet、原生加载、安装器、前端及 Chromium 回归通过。验证使用模拟宿主，尚未连接真实 CPA 或生产账号联调。热重载会等待插件回调，存在短暂观测交接窗口；不承诺前台钩子完全无延迟或无遗漏。旧版本的 Go 映射常驻到进程退出，频繁升级后可择机重启回收内存。回退不兼容旧状态的版本需停服务并恢复对应备份。
