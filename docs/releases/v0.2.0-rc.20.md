# v0.2.0-rc.20 CPA 代理继承、模型目录与同步开销优化

V2 额度查询在未指定账号代理时继承 CPA 全局代理，避免模型请求可用而额度查询直连失败。新增原生按账号模型目录，减少面板全量读取；完整账号身份核对和模型发送保护继续保留。

## 本次改动

- 额度查询通过受限的宿主 HTTP 操作访问固定 wham/usage 地址。显式 direct/none、账号专用代理和独立连接池继续生效；查询前后核对账号绑定，token 仅临时使用。
- HTTP 操作固定到创建它的桥接实例，成功后释放，超时和退出时取消回收。8 路请求阻塞时仍保留取消调用位置；修正单调时钟截止时间取整可能提前取消的问题。
- 接入 `host.auth.models` 并增加只读账号模型目录。前后核对账号 ID、索引、provider 和桥接实例；旧宿主明确不支持时回退管理读取，网络错误或身份变化不触发回退。目录不试发模型，手动模型名仍可使用。
- 30 秒完整身份核对保持原有频率，数据库改为批量合并，只更新变化账号，并以统一同步心跳保留状态新鲜度和旧查询结果防回退保护。绑定确认检查点合并到 5 分钟。
- 单账号已确认启停状态的定期读取使用索引过滤；修改前后的唯一性核对继续保留。SSE 普通正文块在解码元数据前跳过，减少无用分配，保留初始化响应头和 WebSocket 被动额度观察。

## 性能与兼容性

1000 个未变化账号的本地数据库模拟基准中，同步耗时从约 46.8–49.6 ms 降到 4.09–4.61 ms，常规持久行更新从 2001 次降到 1 次。基准包含写入审计触发器，只测数据库阶段，不包含宿主回调或网络；每 5 分钟确认检查点到期时会额外更新绑定行，不代表生产总耗时或真实账号容量。

后台和原生接入层均为 **v0.2.0-rc.20**，数据库保持 **schema 9**，从 rc.13–rc.19 升级无新增迁移。保留已有配置、额度、任务和未知发送防重记录；自动查询及自动唤醒默认关闭，已明确保存的规则保持原有设置。

原生 ABI 仍为 1，RPC schema 继续协商 6/7；宿主提供 schema 8 时可使用 7。原生模型目录需要 CPA 支持 `host.auth.models`；未指定账号代理的查询需要宿主 HTTP 操作回调。必须同时更新后台和接入层，不能把新版后台与旧接入层组合部署。

宿主 `host.http.do` 遵循 CPA 的 HTTP 策略，并在返回前读取完整响应；后台接受的 2 MiB 响应限制不代表 CPA 进程峰值内存上限。完整实现及测量边界见 [API 优化记录](../research/cpa-api-optimization.md)。

## 升级

从任意早期版本升级到 rc.20，须显式 `--restart` 重启 CPA 加载新接入层与管理路由：

```sh
curl -fSL -H 'Cache-Control: no-cache' https://raw.githubusercontent.com/JayConstruct/codex-window-refresh/main/scripts/install-v2.sh -o /tmp/cwr-v2-install.sh
sudo bash /tmp/cwr-v2-install.sh --version v0.2.0-rc.20 --restart
```

后续可使用 `--version latest --restart`，并保留已有部署所需的 `--cpa-dir`、`--service` 或用户服务参数。升级前另存停服务或 SQLite 在线一致备份，不能只复制活动 WAL 数据库主文件；降级须遵循既有数据库恢复限制。操作步骤见 [V2 安装指南](../user/install.md)。

## 验证

本地通过全量 Go 测试、vet、全量 race 检查、42 项原生假宿主测试、246 项 V2 Node 测试、123 项安装器测试和 99 项 V1 面板测试；真实 Chromium 的桌面、移动端及独立自动刷新回归也已通过。新增测试覆盖完整额度查询链路、固定地址与请求头限制、8 路阻塞取消、取消失败重试、操作期限与退出回收、模型目录兼容、同步写入量和状态时序。

amd64/arm64 构建、浏览器检查、发布包校验和下载回归由 [V2 发布工作流](../../.github/workflows/v2-prerelease.yml)执行。尚未使用真实账号查询额度或调用模型，也未进行真实 CPA v8.0.47 的生产联调。
