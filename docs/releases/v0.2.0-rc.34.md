# v0.2.0-rc.34 总览账号开关、快捷唤醒与状态同步

总览和账号表格的操作栏直接显示 CPA 账号开关、查询和“立即唤醒”，不再需要展开更多菜单。开关沿用 CPA 真实认证文件的启用/禁用接口，核对文件名和索引后提交，再读取 CPA 确认真实状态。

“立即唤醒”保持可点击，不根据页面上的旧账号状态置灰。点击后先读取已保存模型，交由后台核查当前账号、凭据绑定、额度、窗口和业务活动；窗口未开启且符合准入条件时才发送，已有活动窗口则记录跳过。禁用或身份无法核实会显示具体原因。重复点击、在途任务以及提交或发送结果未知继续受防重保护，不创建替代请求。

账号开关核实成功后立即通知后台同步。后台每 2 秒读取不含凭据的 CPA 本地目录，发现账号、索引或状态变化时重新核实身份并同步；每 30 秒保留完整凭据绑定校验。目录未变化的轻量检查不读取全部凭据、不刷新完整校验的时间栅栏，也不新增上游额度查询。页面默认每 5 秒读取后台结果，关闭页面后后台检查继续。

模型请求增加 `X-CPA-Plugin-ID: codex-window-refresh`，并用 `X-CPA-Plugin-Action: wake` 或 `prompt_generation` 区分唤醒和候选生成，便于其他 CPA 插件识别。该标记不是认证凭据；内部业务过滤仍使用 CPA 的 `plugin_host_model_callback` 来源。标记是否被发送到上游取决于 CPA 执行器及自定义请求头映射，插件未实现强制剥离。旧记录中的“未标记项目”“调用方未知”“原因未提供”只表示对应元数据缺失，不能据此断定为插件请求，也不能追溯补标。

后台和客户端安装包为 **v0.2.0-rc.34**，接入层保持 **v0.2.0-rc.32**，数据库保持 **schema 12**。从 rc.32 或 rc.33 更新时，安装器确认接入层文件完全一致后可省略 `--restart`，仅更新并重启后台；完成后强制刷新网页。从 rc.31 或更早版本升级仍须显式 `--restart`，同时加载 rc.32 接入层。已有账号、规则、任务和发送防重记录保留，客户端启动器行为沿用 rc.31。

本地验证覆盖全部 Go 测试和 vet、网页测试、同步与模型执行竞态检查、70 项原生端到端测试，以及完整 Chromium 桌面/手机、自动刷新、项目匹配、额度状态、登录和调用方名称回归。验证使用模拟账号和响应；发布流程另执行 amd64/arm64 构建、完整竞态检查、打包及公开安装包回读验证。
