# v0.1.0-rc.13 测试版

优化长期页面刷新、分区查询策略和计划时间轴，修复不可用账号无法手动查询的问题。

## 本次变化

- 页面自动刷新仍默认关闭，手动开启后持续读取状态及当前生效配置；失败采用 10/20/40/60 秒退避，成功后恢复 5 秒，并隐藏对应读取错误，不覆盖未保存草稿。断网暂停，恢复联网、回到前台或重新聚焦后补读；认证失效停止，不自动重试写操作。
- 增加独立的“后台标签页继续刷新”选项，默认关闭。浏览器冻结或电脑休眠期间不能保证执行，返回后补读；自动轮询取消不影响保存或其他操作。
- 查询和唤醒分别把 5 小时、7 天（周）额度设置为独立卡片。到期自动查询与定期查询各自配置排除时段、随机延迟上下限；每类可选择参与定期查询并设置间隔，仍需定期查询总开关开启。
- 查询排除时段按规则时区，支持跨午夜、多区间和全天排除；延迟到期仍处于排除时段时顺延。随机值依据账号、凭据代际、窗口和触发边界稳定生成，读取预览不会重新抽取。单账号额度请求可能同时更新两类额度，同账号查询合并执行；排除不阻止手动查询、被动采集、发送前核对及已发请求验证。
- 未来查询与唤醒计划改为按规则时区分日的时间轴，区分查询、模型唤醒与阻塞状态，展示账号、模型、执行时间或随机范围。定期查询以循环节点表示；计划考虑查询延迟、排除时段和退避，不额外发起请求或推算未知服务端窗口。
- CPA 禁用或暂不可用账号现在支持单账号与批量手动额度查询；查询仍校验账号身份、凭据代际及查询前后绑定，不解除禁用，不发送模型请求。账号移除、凭据失效及绑定变化仍会跳过或失败；模型唤醒的账号可用性保护保持不变。
- 将混合的“账号已禁用”标签改为“CPA 账号不可用”，避免把额度耗尽导致的暂不可用误认为确定禁用。旧配置保持公共查询间隔、开关和既有唤醒策略；新排除时段为空、查询延迟为零，不意外开启自动功能。

## 安装或升级

已有 CPA 的 Debian 12/13 服务器执行：

```sh
curl -fSL https://raw.githubusercontent.com/JayConstruct/codex-window-refresh/main/scripts/install.sh -o /tmp/codex-window-refresh-install.sh && sudo bash /tmp/codex-window-refresh-install.sh --version v0.1.0-rc.13
```

升级保留策略与状态，默认重启已核实的 CPA systemd 服务，可能短暂中断请求；使用 `--no-restart` 推迟重启。root 会话可省略 sudo。路径或服务无法唯一识别时，沿用 `--cpa-dir`、`--service`、`--user-service`、`--user` 等参数。Docker 部署按安装指南替换插件。

重启 CPA 后刷新网页。在“额度查询”分别设置两类到期/定期策略并保存；“未来计划”需要独立开启并保存。页面自动刷新及后台刷新选项无需保存，重新打开或断开后恢复关闭。

## 验证与边界

本地全量 Go 测试、race、vet、41 项前端逻辑测试、78 项安装器测试及原生 ABI 加载检查通过。新增回归覆盖查询排除/延迟、独立间隔、时区和夏令时、计划只读、轮询恢复与取消、不可用账号只读查询、查询前后凭据代际变化，以及查询不解除禁用或触发唤醒。发布流程要求 Chromium 浏览器验证和 Linux amd64、arm64 构建、安装器测试、原生加载检查全部通过，才上传安装包与 SHA256SUMS。

仍要求 CPA ABI 1 / RPC schema 6，尚未在真实 CPA 宿主或生产账号上联调。浏览器后台限速、冻结及电脑休眠不能由网页绕过；宿主同步 C 回调完全不返回时不能强行中断。查询不自行刷新 OAuth，时间轴仅为预计计划，模型发送仍遵守窗口、前台请求及重复送达保护。
