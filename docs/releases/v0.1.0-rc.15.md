# v0.1.0-rc.15 测试版

修复手动查询持续显示“已排队”、旧刷新覆盖新结果，以及单个异常账号阻塞全部查询的问题，统一面板与后台的数据同步。

## 本次变化

- 面板运行数据改为单次读取版本化 `/snapshot`，账号、额度、任务、能力和生效配置来自同一已发布运行视图。前端校验读取顺序、写操作和实例版本，迟到的旧响应不会覆盖新额度或已保存设置。
- 额度查询、手动唤醒和内容生成均按稳定 `job_id` 跟踪。即使关闭页面持续刷新，操作期间也会读取进度，结束后停止；读取失败保留已知结果和未保存草稿，不重提操作。多页面查询不再因“最近任务”被替换而一直等待。
- 最近 64 个任务结果保留在运行时内存；重启、记录淘汰和送达不确定都有明确提示。模型派发意图与送达抑制继续持久化，未知送达不会自动重发。
- 接受任务即可读取其排队状态，逐账号发布进度；成功结果与已提交账号证据在同一发布边界可见，持久化失败不会显示虚假成功。
- 单账号凭据或身份绑定错误隔离为禁用占位账号，健康账号继续查询；无效账号不会得到可发送绑定，手动额度查询明确计为失败。全局清单或能力故障显示阻塞原因和下次检查时间，任务开始后超过两分钟仍被阻塞时，在调度检查中失败并释放操作占用。
- 新增通用 `make release-check`，供本地、CI 和打包共用，核对发布标签、插件内置版本及对应发布说明，避免包名和插件版本不一致。

## 安装或升级

已有 CPA 的 Debian 12/13 服务器可指定版本升级：

```sh
curl -fSL https://raw.githubusercontent.com/JayConstruct/codex-window-refresh/main/scripts/install.sh -o /tmp/codex-window-refresh-install.sh && sudo bash /tmp/codex-window-refresh-install.sh --version v0.1.0-rc.15
```

升级保留已有策略、模型和状态；安装器默认重启已核实的 CPA systemd 服务，可能短暂中断请求。使用 `--no-restart` 可稍后手动重启。路径或服务不明确时沿用 `--cpa-dir`、`--service`、`--user-service`、`--user` 等原安装参数；Docker 部署按安装指南替换插件。

替换插件并重启 CPA 后刷新管理网页，前后端需同时更新。先执行一个健康账号查询，再检查批量结果；自动查询和自动模型唤醒仍需独立开启。无需清空状态或运行旧数据迁移程序。

## 验证与边界

本地全量 Go 测试、竞态检测、vet、66 项面板逻辑测试、Chromium 回归、安装器与发布检查、原生 ABI 加载均通过。新增集成验证使用真实运行时和本地模拟宿主，覆盖健康与异常账号混合查询、任务身份、并发发布及结果一致性。发布流程在 Linux amd64、arm64 各自测试和原生加载通过，并完成浏览器检查后，才发布安装包和 SHA256SUMS。

仍要求 CPA ABI 1 / RPC schema 6；尚未连接真实 CPA 宿主或生产账号验证。任务记录的 64 项上限不代替持久化执行历史；未发送任务不会跨重启恢复。两分钟阻塞期限在调度检查时判断，不能强行终止完全不返回的同步宿主 C 回调。插件不自行刷新 OAuth；浏览器冻结或电脑休眠期间不能保证页面更新。
