# v0.2.0-rc.26 客户端目录自动发现与一键安装

客户端启动器默认根据项目目录生成稳定的 SHA-256 标识，无需维护 projects.json。在 Git 项目内使用最近的项目根目录，普通目录使用启动目录；解析符号链接后，同一项目的子目录共用标识。请求携带 X-CWR-Project 和短目录名，不上传完整路径。原有 --project 与已有目录映射继续优先生效；目录移动会生成新标识，相同操作系统和相同绝对路径在不同电脑上生成相同标识。

服务端“账号调度与重置卡”新增最近出现的客户端项目，显示目录名、标识及最近出现时间，支持搜索和分页。点击项目可命名并选择首选账号，保存后由服务端维护偏好，无需回传映射。首次请求使用现有选号规则，后续新会话应用已保存偏好；已有会话绑定保留。观察与配置 revision 独立，刷新保留草稿；最多保存最近 1024 个项目。接入层只记录已认证、候选全部属于 Codex 的正常业务请求，内部调用和探测不参与，不增加模型请求。

移除客户端提供商与 profile 配置检测及 TOML 依赖。通过脚本启动时传入项目请求头设置，直接运行 codex 则不额外添加。--provider 指定本次使用的提供商 ID，默认 cpa；脚本不切换提供商、不修改 Codex 配置和请求正文。

新增 Linux/macOS 客户端安装器 scripts/install-client.sh，需要 Python 3.10+，在线安装另需 curl。无需 sudo，默认安装到 ~/.local/bin，提供 cwr-codex 命令和兼容旧路径的 cwr-codex.py。安装器下载配套版本的固定标签源码并校验 SHA-256，再替换脚本；下载或校验失败保留旧安装。支持 --bin-dir、自定义目录和已解压发行包中的离线安装。重新下载并运行安装器即可更新，不修改目录映射、Codex 配置或 shell 配置。

后台与原生接入层均为 **rc.26**，必须同时更新并显式 **--restart**。客户端也需运行新版安装器；页面需刷新。数据库从 schema 10 升至 **schema 11**，只增加项目观察记录，保留账号、规则、额度和兑换防重状态；安装器保留升级失败回滚用的一致备份。schema 11 不能直接交给 rc.25 或更早后台，手动降级须恢复对应的一致备份。

验证覆盖 Go 全量测试、vet、竞态检查，目录标识及中文目录名、旧映射兼容、客户端安装更新/离线安装及失败保留、观察重放与容量限制、schema 10 升级、完整原生桥到后台的发现/保存/选号/重启链路。Chromium 覆盖完整面板、自动刷新、项目匹配及 320/390/768/1586 像素布局。发布流水线在 amd64/arm64 构建并校验公开安装包、安装更新及回滚；使用临时数据和模拟宿主，未操作真实账号或重置卡。

使用步骤见[项目与账号](../user/account-scheduling.md#项目与账号)，服务器升级见[V2 安装与更新](../user/install.md)。
