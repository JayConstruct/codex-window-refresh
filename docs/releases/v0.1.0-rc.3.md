# v0.1.0-rc.3 测试版

从 CPA 管理中心打开模块时自动复用已保存的登录凭据，刷新或重新打开不再重复要求输入管理密钥。

## 本次变化

- 支持同源 CPAMC/CPAMP 的 `cli-proxy-auth` 和旧版 `managementKey`，兼容 JSON、旧版纯字符串和 `enc::v1::` 混淆格式；已保存的服务器地址必须匹配当前 CPA 源与反向代理前缀。
- 没有可用凭据、浏览器存储受限或认证失效时，保留手动登录。自动连接只进行一次认证探测，失败不重试，不改变 CPA 的登录状态。
- 模块只读取宿主已有存储，不持久化手动输入的密钥。断开后保持断开；重新打开或刷新才重新尝试复用。
- 发布流程增加真实 Chromium 的自动连接、刷新、重新打开、菜单 iframe 和失效回退验证，两种架构构建和浏览器检查全部通过后发布。
- 包含 rc.2 发布后主分支已有的安装器更新：首次安装自动识别 Codex 模型、只读模型诊断，以及 systemd 系统服务和用户服务支持。

## 安装与升级

重新下载并运行安装脚本，沿用原 CPA 路径和服务参数：

```sh
curl -fL https://raw.githubusercontent.com/JayConstruct/codex-window-refresh/main/scripts/install.py \
  -o /tmp/codex-window-refresh-install.py
sudo python3 /tmp/codex-window-refresh-install.py --cpa-dir /root/cliproxyapi --version v0.1.0-rc.3
```

重启 CPA 后刷新管理中心，在插件菜单打开 **Codex Window Refresh**。同源管理中心已保存凭据时会直接连接；管理中心没有保存凭据或跨源部署时仍需手动输入管理密钥。

提供 Linux `amd64`、`arm64` 安装包及 `SHA256SUMS`，支持 Debian 12/13；Alpine/musl 不适用。升级保留已有策略、私有管理密钥环境文件和窗口状态。

## 验证与边界

新增凭据兼容、服务器地址匹配、异常存储回退测试；浏览器模拟 API 覆盖自动连接和原有账号、规则保存与认证清理行为。发布流程另执行 Go 测试、race、vet、原生假宿主加载、安装器测试和两种架构打包校验。

尚未在真实 CPA 宿主和生产账号上联调。管理接口仍受 CPA 管理密钥鉴权，自动连接只读取本地快照，不主动查询上游额度或发送模型请求。后台实际生成并发仍为 1，其他运行边界见 [运行时说明](https://github.com/JayConstruct/codex-window-refresh/blob/v0.1.0-rc.3/docs/runtime.md)。
