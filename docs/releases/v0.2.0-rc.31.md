# v0.2.0-rc.31 自动登录与 Codeman 客户端接入

页面新增“记住密钥并自动登录”，默认不勾选。成功连接后按 CPA 来源与反向代理路径保存本页登录，刷新或重新打开时自动验证并连接。未勾选时密钥仅在内存中；主动断开或收到 401/403 后清除保存的密钥并关闭该地址自动登录。继续只读复用 CPA 已保存的登录，不修改 CPA 的登录存储。保存格式使用与 CPA 相同的可逆混淆，不构成加密保护；存储不可用时提示原因，当前页面连接仍可继续。

客户端安装器检测到 `~/.codeman/app` 时，自动配置 Codeman 的 Codex 启动入口。使用 Codeman 已安装的 CLI 注册表模块读取和校验当前启动模板，保留其他 CLI、Codex 开关、模型、推理强度、动画及恢复会话参数。已有 `clis.json` 首次变更前另存私有备份，重复安装不叠加启动参数；无效注册表或自定义 Codex 启动命令不覆盖。可用 `--codeman-dir` 指定数据目录，`--no-codeman` 只安装客户端，已有客户端可用 `--setup-codeman` 单独配置。

Codeman 接入需要 Node.js 及支持 CLI 注册表的 Codeman；**安装后重启 Codeman 服务**，新建和恢复的 Codex 会话才使用新入口。原始 Codex 程序、Codex 配置和 shell 配置保持不变；终端仍可使用 `cwr-codex`。启动器支持原生 `-C`/`--cd` 目录参数，项目标识按最终工作目录计算。

后台和客户端版本为 **v0.2.0-rc.31**，接入层保持 **v0.2.0-rc.28**，数据库保持 **schema 12**。从 rc.28–rc.30 更新时，安装器确认接入层文件完全一致后可省略 `--restart`，仅更新并重启后台；完成后强制刷新网页。客户端可单独更新。服务端从 rc.27 或更早版本升级仍须显式 `--restart`，并遵循 schema 12 的备份与回退要求。

本地验证覆盖全部 Go、Python 和网页测试、原生假宿主端到端及 Chromium 桌面/移动端自动登录。Codeman 接入使用其实际注册表与命令渲染器，在临时目录中启动假 Codex，验证项目头、模型、推理强度、恢复及退出码，不修改真实 Codeman 注册表、不发送模型请求。发布流程执行 amd64/arm64 构建与公开安装包回读验证。
