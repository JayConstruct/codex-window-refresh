# v0.2.0-rc.32 调用方识别与重置卡 HTTP 通道修复

修复接入层仅从 `Metadata.caller_scope` 读取调用方的遗漏，兼容 CPA 独立的 `CallerScope` 字段；后续事件未重复提供时保留同请求已观测的身份。用户请求列表、详情、调用方筛选和分流分析优先显示当前浏览器、当前 CPA 地址下保存的 API key 名称/说明。名称只在本地读取，原始 Key 只在浏览器内存中用于计算摘要，不上传插件后台；没有本地名称时仍显示调用方摘要。历史记录若完全缺少可关联的调用方标识，无法补造归属。

改善账号可用状态：已有正数余额且未越过已知重置边界的账号可显示额度可用，活动窗口容量仍单独统计，自动唤醒和调度继续遵循各自的新鲜证据要求。五小时窗口到期后，若查询任务正在随机延迟队列中，显示“X 秒后查询”并每秒更新；倒计时本身不新增请求，到期后等待真实额度查询结果。

重置卡详情和兑换默认使用 CPA HTTP，无需安装 Codex CLI。只允许固定上游详情 GET 和 consume POST；兑换发送选定的 `credit_id` 及已持久保存的 `redeem_request_id`，未知回执继续保留同卡片、同操作 ID 的防重保护。默认继承 CPA 全局代理，账号显式代理/direct 优先，也可设置 `--reset-proxy`。只有显式设置 `--codex-binary` 时启用 CLI 兼容通道，HTTP 失败不会自动切换通道重发。

卡片数量优先复用现有额度查询和真实业务 WebSocket 实际报告的计数，每账号可手动“查询卡片数量”。取消固定十五分钟详情轮询，可选按数量变化、详情失败重试及自动使用条件补查，按账号至少间隔一分钟。缺失字段保留未知；数量和详情各有独立观测时间。自动补全详情与自动兑换开关仍分别控制，默认关闭；手动数量查询不兑换卡片、不发送模型请求。

后台、客户端安装包和接入层均为 **v0.2.0-rc.32**，数据库保持 **schema 12**。从 rc.31 或更早版本升级须使用 `--restart`，同时更新后台与接入层并重启 CPA；仅重启后台无法加载新采集字段、HTTP 白名单及身份匹配路由，更新后强制刷新网页。已有账号、规则、任务、查询和兑换防重记录保留。客户端启动器内容沿用 rc.31，已有客户端可继续使用。

本地验证覆盖 Go、网页、安装器及原生模拟宿主测试，并在 Chromium 验证调用方名称、筛选身份、桌面/移动端布局、可用状态、查询倒计时和手动卡片数量查询。重置卡测试使用模拟 HTTP/CLI 回执，未操作真实卡片。发布流程在 amd64/arm64 完成构建、竞态检查与公开安装包回读验证。
