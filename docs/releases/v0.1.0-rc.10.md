# v0.1.0-rc.10 测试版

修复点击“查询此账号”时因宿主 RPC 方法名不匹配而失败的问题，并补齐额度查询诊断与连接检查。

## 本次变化

- 将原生 HTTP 操作接口修正为 CPA 官方的 `host.http.operation_open`。旧版插件的错误方法名会在真正发出 HTTP 查询前被宿主拒绝；仅升级 CPA 无法修复旧动态库。
- 新增“检查宿主查询接口”按钮，显式创建并取消一个本地宿主操作，不查询账号、不访问上游，也不发送模型请求。配置可用、宿主接口检查通过与真实账号查询成功分别显示。
- 查询失败按阶段分类：宿主操作创建、代理、管理接口认证、上游 401/403/429/5xx、超时、响应格式与大小异常。卡片、批量任务和最近失败诊断显示固定原因、HTTP 状态及耗时，不返回凭据或远程错误正文。
- 兼容账号代理字段 `proxy_url`、`proxyUrl`、`proxy-url`、`proxyURL`；冲突值阻止查询。补齐与官方管理面板一致的查询请求头。
- 查询设置增加“单账号查询超时”，默认 15 秒，可配置 1 秒至 5 分钟。查询失败保留已有额度，不自动改用管理桥。

## 使用和升级

重新下载主分支安装脚本，或使用本版安装包内的 `install.py`，指定 `--version v0.1.0-rc.10`，沿用原 CPA 路径、服务、用户及额度传输模式参数。升级保留已有策略、窗口状态和私有环境文件。

替换插件后重启 CPA、刷新管理面板。在宿主模式下先点击“诊断与高级 → 检查宿主查询接口”，再执行一次“查询此账号”，用实际查询结果确认账号凭据及上游连接。管理桥模式继续使用已有管理地址与密钥设置。

## 验证与边界

本地全量 Go 测试、race、vet、安装测试、面板逻辑测试、原生 ABI 加载和 Chromium 浏览器验证通过。原生假宿主检查 ABI 1 / RPC schema 6，22 次宿主返回的缓冲区全部释放；自动与单账号额度查询共 2 次，模型请求数为 0。发布流程还要求 Linux amd64、arm64 各自完成构建及验证，然后上传安装包与 SHA256SUMS。

尚未在真实 CPA 宿主或生产账号上联调。`host.auth.get` 读取物理凭据文件，可能落后于宿主内存；非标准嵌套凭据仍有兼容边界。插件不自行刷新 OAuth，也不保存或旋转凭据。宿主同步 C 回调若完全不返回，Go 超时不能强行中断该回调。本地接口检查通过不代表上游可达。

问题核对与社区方案对比见 [额度查询检查记录](https://github.com/JayConstruct/codex-window-refresh/blob/v0.1.0-rc.10/docs/quota-query-review.md)。
