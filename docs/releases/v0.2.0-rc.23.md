# v0.2.0-rc.23 插件统一管理主会话与子代理粘性

开启业务账号调度后，插件接管 Codex 主会话、子代理、分支和压缩后会话的账号绑定。已有有效绑定优先于项目偏好、额度重置时间及恢复可用的更高优先级账号；首次分配仍尊重 CPA 最高可用优先级、模型支持、禁用、冷却和显式指定账号。

子代理默认继承父账号后保存独立绑定，子代理重选不改写父记录；绑定按调用者、项目、提供商、请求模型和规范会话 ID 隔离。只使用 CPA 提供的会话/父会话元数据或会话请求头，不读取提示词来推断亲缘关系。客户端或宿主缺失父标识时无法继承。

“账号调度与重置卡”设置页新增子代理继承开关、失败重绑条件和会话空闲失效时间。默认在额度或认证失败时重绑，临时上游故障保留原绑定并允许本次回退；可选临时故障也重绑。账号被替换、删除、禁用或取得新鲜耗尽证据时，旧绑定失效。并发满或正在兑换的绑定账号返回繁忙，不因并发临时换号。

按宿主选号 ID 跟踪预约和单次上游执行结果，覆盖宿主内部换号重试后最终成功的情况；迟到的旧结果不能清除后来的新绑定。结果通知不读取或保存客户端 API key、失败正文、提示词和 token 用量。后台快照短暂中断时，插件保留内存绑定、继续使用宿主可用候选，停止使用过期额度排序；已知兑换保护继续保留。

后台与原生桥均为 rc.23，升级必须显式 `--restart`。数据库保持 schema 10，从 rc.21/rc.22 升级无需迁移，原有规则、额度及发送防重记录保留，已有调度开关不变。旧配置默认补充子代理继承开启、额度或认证失败时重绑。绑定仅在原生桥内存中，默认空闲三十分钟失效，CPA 重启后重新建立。接管以 CPA v8.0.47 的插件契约为基线，CPA 原有粘性设置无需改写。

本地验证通过 Go 测试、vet、竞态检查、63 项原生桥测试及 247 项前端测试；17 项粘性场景通过 AddressSanitizer/UndefinedBehaviorSanitizer。真实 Chromium 覆盖桌面/手机布局、旧设置默认值、粘性设置保存和回读。发布流水线分别在 amd64/arm64 构建、测试，并对公开安装包校验和、安装更新及回滚进行验证。测试使用模拟宿主和模拟账号，未操作真实账号或重置卡。

使用及边界见[账号调度与插件粘性说明](../account-scheduling.md)，安装见[v2 更新指南](../backend-v2-install.md)。
