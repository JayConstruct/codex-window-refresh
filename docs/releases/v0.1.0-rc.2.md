# v0.1.0-rc.2 测试版

新增 CPA 网页面板、规则保存和自动安装升级脚本。

## 本次变化

- 中文面板显示账号 5 小时和周额度、实际重置倒计时、合并任务、调度容量及阻塞原因，支持搜索和状态筛选。
- 规则表单、每日时间规则、完整 JSON 编辑器和账号暂停草稿；保存严格校验并原子写入策略、热应用，版本冲突保留草稿。
- 管理密钥仅保存在页面内存，动态请求限制在 CPA 同源管理接口；认证失效、断开和刷新会清除密钥及数据。
- 安装脚本默认选择最新已发布正式版或 rc 测试版，保留 `--version` 固定版本；支持预览、SHA-256 校验、备份、升级及卸载，保留已有规则和窗口状态。
- 补齐 CPA 加载器要求的 `GitHubRepository` 注册字段，并更新宿主显示的版本为 `0.1.0-rc.2`。

## 安装与升级

支持 Debian 12/13 的 `amd64`、`arm64`，安装包在 Debian 12 bookworm 环境原生构建。下载对应架构安装包并用 `SHA256SUMS` 校验；包内包含 `.so`、配置检查工具、默认关闭自动请求的策略、安装脚本、构建信息和许可说明。Alpine/musl 不适用。

重新下载脚本并沿用原安装路径、服务和工作目录参数：

```sh
curl -fL https://raw.githubusercontent.com/JayConstruct/codex-window-refresh/main/scripts/install.py \
  -o /tmp/codex-window-refresh-install.py
sudo python3 /tmp/codex-window-refresh-install.py --cpa-dir /root/cliproxyapi
```

默认解析到最新发布版；需要固定本版时添加 `--version v0.1.0-rc.2`。systemd 部署添加原有 `--service 实际服务名`，可加 `--restart`；直接运行模式按原方式重启。已有策略、管理密钥环境文件和窗口状态保留。

重启后，从 CPA 插件菜单打开 **Codex Window Refresh**，或访问同源路径 `/v0/resource/plugins/codex-window-refresh/status`，输入 CPA 管理密钥连接。

详细说明：[安装指南](https://github.com/JayConstruct/codex-window-refresh/blob/v0.1.0-rc.2/docs/install.md)、[面板使用](https://github.com/JayConstruct/codex-window-refresh/blob/v0.1.0-rc.2/docs/panel.md)。

## 验证与边界

本地通过 Go 测试、race、vet、原生假宿主加载、29 项安装脚本测试、14 项前端行为测试，以及真实 Chromium 的桌面和移动端模拟 API 交互验证。发布流程要求两种架构分别通过测试、原生加载和打包检查后上传安装包。

尚未在真实 CPA 宿主和生产账号上联调。要求原生插件 ABI 1、RPC schema 6，接口核对基于官方提交 `3de4e248f6bb12fc7dfafb183404f3b248578922`。后台实际生成并发仍为 1；缺少有效窗口证据时不会猜测新窗口，前台请求和后台发送之间仍有宿主竞态。

CPA `home.enabled: true` 时关闭插件资源路由；远程使用动态面板还需要宿主允许远程管理。网页保存会重新序列化策略，保留权限和所有者，但不保留 YAML 注释。保存或重新加载启用规则可能触发真实模型请求。
