# v0.2.0-rc.37 Key 集中管理与执行中账号展示

“账号”增加“上游账号 / API Key”子页签。API Key 页集中展示 CPA 已配置的 Key，包括尚无请求记录的 Key；支持按名称或打码值搜索、分页、修改及清除名称。名称继续与同一浏览器、同一 CPA 地址下的管理中心共用，不跨设备同步，也不修改实际 Key 清单。

Key 列表的“查看请求”按真实来源标识进入用户请求页，清除旧的项目、账号、会话等筛选，查看全部保留时间内的记录。运行记录的 Key 筛选改为可搜索下拉，同时显示名称和打码值，支持重名区分、键盘选择和取消；输入仅搜索候选，选中后才读取对应请求。列表统一称为“API Key / 模型”，详情合并重复来源字段；未命名时只显示一次打码值，匹配失败时保留短来源摘要。

“为什么分到这个账号”改用一句话说明主因，详细选号信息默认收起。仅在记录有 HTTP 429 时显示相关解释，不把限流直接当成额度耗尽。刷新 Key 清单时保留已知名称，读取失败后撤销旧匹配及改名入口。

执行中的用户请求在账号选定后立即显示当前账号，无需等待用量返回。重试换号时以最新生命周期 selection ID 匹配当前账号和原因，旧账号的迟到结果不覆盖当前选择。选号本身不计作已执行尝试，也不补造 Token、耗时或费用；完成后的账号和统计仍以实际执行证据为准。

原有会话粘性在选号时就建立绑定，覆盖预约及执行中的请求。本次补充验证首个请求尚未完成时，同会话请求和开启继承的新子会话沿用该绑定；预约及执行中的请求均计入并发上限，满额返回繁忙，不为并发临时换号。本次未修改原生选号算法。

后台与客户端安装包为 **v0.2.0-rc.37**，原生接入层保持 **v0.2.0-rc.36**，数据库保持 **schema 12**。从 rc.35 或更早版本升级须显式 `--restart`，加载配套接入层；已有 rc.36 按安装器检测更新，若提示接入层二进制变化，同样须使用 `--restart`。已有账号、规则、任务和发送防重记录保留，更新后强制刷新网页。客户端启动器行为不变，已有客户端可继续使用。

回归覆盖执行中账号展示、迟到结果与重试换号、未完成请求的会话绑定及并发保护、Key 清单与搜索、重名选择、名称冲突/删除，以及桌面和手机布局。发布工作流在 amd64/arm64 构建和测试，发布独立安装包及 SHA-256，并回读公开安装包验证。测试使用模拟账号和响应，不等于真实账号或生产负载验收。
