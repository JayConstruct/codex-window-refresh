# v0.1.0-rc.5 测试版

新增独立的自动/手动额度查询控制，不发送模型请求；继续支持用户正常请求返回的被动额度更新。

## 本次变化

- 规则页面新增“定期查询额度”“允许手动查询额度”开关及查询间隔，设置保存后生效。查询间隔默认 30 秒，允许 30 秒到 1 小时；旧策略自动继承兼容默认值。
- “运行概览”新增“立即查询额度”按钮及进度。一次任务分批查询 CPA 启用的 Codex 账号，包括只暂停模型唤醒的账号；每周期最多 4 次，重复点击合并，失败计数且该次手动任务不重试。
- 手动查询处理走仅查询路径，不创建唤醒任务、不派发模型，也不调用“重新检查规则”。自动额度查询与模型唤醒开关独立。
- 原“启用自动刷新”改为“启用模型唤醒（会发送模型请求）”。只想查额度时关闭模型唤醒，可保留定期/手动查询及用户响应被动采集。
- 查询关闭不影响用户 HTTP/流式响应和 WebSocket 额度事件。完整被动额度可按配置间隔推迟重复查询；模型唤醒独立开启时，发送前核对与已有操作验证仍保留。

## 使用和升级

更新至本版后重启 CPA，刷新管理中心。在“刷新规则”关闭“启用模型唤醒”，设置“额度查询设置”，点击“保存并应用”；然后在“运行概览”按需点击“立即查询额度”。桥未就绪或禁止手动查询时按钮禁用。

重新下载并运行安装脚本，沿用原 CPA 路径、服务和用户参数，指定 `--version v0.1.0-rc.5`。升级保留已有策略、私有管理密钥环境文件和窗口状态；提供 Linux amd64、arm64 安装包及 SHA256SUMS。

## 验证与边界

回归验证自动查询开关、配置间隔、模型关闭时零模型请求、被动更新保留、手动批量预算、暂停账号仍可查询、重复任务合并、失败不重试、手动权限和参数限制、原生加载，以及浏览器中的设置保存、查询进度、额度更新和模型配置保留。

手动任务不持久化，重启后不恢复；关闭手动查询会取消剩余任务，已开始查询正常结束。独立开启的模型唤醒规则仍可能在其他调度周期发送模型请求；仅查询时必须关闭模型唤醒。已发出的模型请求不会被撤回。仍要求 CPA ABI 1 / RPC schema 6；尚未在真实 CPA 宿主或生产账号上联调。
