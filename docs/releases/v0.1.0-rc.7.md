# v0.1.0-rc.7 测试版

每个账号新增手动查询剩余额度的按钮，只查询选中的账号，不发送模型请求。

## 本次变化

- “账号额度”卡片新增“查询此账号额度”，无需展开诊断。查询后更新该账号的 5 小时及周窗口，显示排队、完成或失败状态。
- 单账号查询与总览的批量查询共用“允许手动查询”开关。暂停模型唤醒的账号仍可查询；CPA 已禁用或已移除的账号不发起请求。
- 同一时间只执行一个手动任务，相同目标重复点击会合并，不同目标不会混入现有任务。失败保留已有额度，不自动重试。
- 管理 API `POST /quota-query` 支持可选请求体 `{ "account_id": "账号 ID" }`，不传时继续批量查询。摘要中的 `scheduler.quota_query.account_id` 标识单账号目标。

## 使用和升级

更新后重启 CPA 并刷新管理中心。在“额度查询”开启“允许手动查询”并保存，然后在“账号额度”点击需要查询的账号按钮。额度桥未就绪、后台未运行或手动查询关闭时，按钮不可用。

安装脚本指定 `--version v0.1.0-rc.7`，沿用原 CPA 路径、服务和用户参数。升级保留已有策略、私有管理密钥环境文件和窗口状态；提供 Linux amd64、arm64 安装包及 SHA256SUMS。

## 验证与边界

通过单账号绑定、暂停账号查询、已禁用或移除账号跳过、重复请求合并、权限取消、失败不重试及零模型派发测试；浏览器验证按钮、排队期间禁用、结果显示、失败提示、特殊账号 ID 和手机布局。继续执行 Go 检查、竞态检测及原生加载验证。

查询接口不创建模型唤醒任务；独立开启的模型唤醒规则仍可能在其他调度周期发送模型请求。手动查询任务不持久化。仍要求 CPA ABI 1 / RPC schema 6；尚未在真实 CPA 宿主或生产账号上联调。
