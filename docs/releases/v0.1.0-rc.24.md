# v0.1.0-rc.24 测试版

修复五小时额度恢复后自动唤醒一直等待，以及“下一次唤醒”每隔几秒向后移动的问题。

## 变化

- 已知五小时窗口确实到期、对应唤醒计划已经成熟，且新查询返回满额占位值并允许请求时，可按原计划执行一次自动唤醒。仍受模型唤醒开关、CPA 可用性、账号暂停、人数容量、时段、前台请求、退避及发送抑制约束。
- 满额占位值继续显示“尚未确认窗口启动”，不建立新的五小时倒计时或基线。已确认的未来窗口、缩短倒计时、缺少到期基线、过期或不完整额度仍不能据此自动发送；实际活跃额度证据才确认启动。
- 已发送但未确认的请求继续等待验证，包括重启后的情况；满额占位值不能确认已启动，也不会触发重复发送。手动查询仍只读，不因本次查询直接派发模型请求。
- 计划增加原定时间、等待原因和下次核对时间。已到期的任务保留原定随机延迟结束时间，页面不再把移动的检查时间显示为新唤醒时间；适用于已分配的五小时、周及每日任务。

## 升级

使用原一键脚本更新。rc.21 及以上版本默认热重载，无需重启 CPA，也不用清空已有策略、窗口或任务。真实 CPA 和生产账号行为仍需现场验证。

## 验证

回归覆盖五小时到期后满额预检、先手动查询再自动执行、等待人数后恢复、未来窗口和缩短倒计时阻止发送、证据新鲜度与绑定、未知送达跨重启抑制重复发送，以及原定时间与检查时间分开显示。发布要求 Go、竞态、原生热重载、安装器、前端、Chromium 和双架构构建通过。
