# v0.2.0-rc.38 客户端模式切换与 CPA 项目头保护

客户端增加 `auto`、`official`、`cpa` 三种模式，Codeman 继续使用同一个启动入口，保留模型、推理强度、动画和恢复会话参数。`cwr-codex --set-mode official` 保存官方 ChatGPT 登录模式，跳过项目标识生成与项目头注入，以本次启动参数使用官方提供商及地址，不改写 Codex 配置。需要登录时可运行 `cwr-codex -- login`，远程环境可加 `--device-auth`。模式切换在 Codeman 下次启动 Codex 进程时生效，正在运行的会话保持原模式，无需为切换模式重启 Codeman。

默认 `auto` 模式通过 Codex 原生 `config/read` 读取生效配置及本次 `-c` 覆盖，只有完整 API 地址匹配用户登记的 CPA 地址时才添加 `X-CWR-Project` 与可选目录名头。匹配后固定本次启动的提供商和地址；协议、主机、端口和路径均参与核对。官方域名不可登记为 CPA，内置提供商不添加项目头，未登记或无法确认的目标继续使用原生启动参数且不新增项目头。自动模式只决定是否添加项目头，不根据登录身份切换请求路由。

**客户端升级后需要登记 CPA 地址。** rc.27–rc.37 的客户端默认向已记住的提供商或 `cliproxyapi` 注入项目头；本版取消该无条件行为与提供商交互修复。原设置中未保存模式时使用 `auto`，没有登记地址就不添加项目头；已明确保存的 `official`、`cpa` 模式保留。需要项目调度时，在运行 Codeman 的同一用户下执行以下命令，将示例地址替换为 Codex 配置中的实际完整 CPA API 地址：

```sh
cwr-codex --trust-cpa-url http://127.0.0.1:8317/v1
cwr-codex --set-mode auto
cwr-codex --status
```

显式 `cpa` 模式要求配置检测与地址匹配成功，否则报错并停止；旧提供商 ID 作为该模式的额外匹配约束保留。当前 Codex app-server 不能可靠处理 CLI profile，遇到 profile、本地模型、远程服务、受组织策略管理的提供商、单独的模型目录地址或配置读取失败时，`auto` 不加头，`cpa` 停止。客户端不会移除用户自己配置的请求头，也不控制已登记 CPA 的重定向或上游转发规则。

模式、提供商约束和登记地址保存在客户端 `client.json`，安装更新保留设置，修改时使用 `0600` 权限和临时文件替换。损坏设置会明确报错，不会静默切换路由或覆盖原文件。客户端不读取或复制登录凭据，官方模式仅为子进程移除 API Key 和地址环境覆盖，保留代理与证书配置；登录及凭据更新仍由 Codex 管理。

后台与客户端安装包为 **v0.2.0-rc.38**，原生接入层保持 **v0.2.0-rc.36**，数据库保持 **schema 12**。本次功能只需在运行 Codeman 的电脑更新客户端，不要求同步升级服务端。服务端仍按现有安装器更新；从 rc.35 或更早版本升级须显式 `--restart`，若安装器提示接入层二进制变化也须重启 CPA。账号、规则、任务和发送防重记录保留。

客户端回归覆盖三种模式、地址登记、官方域名与歧义 URL 拒绝、端口和路径匹配、配置覆盖、超时及无效协议处理、设置保留、Codeman 实际命令渲染，以及真实 Codex 向本地模拟 HTTP 服务发送的请求头。模拟服务固定返回错误，不执行模型推理，不访问真实账号。发布工作流在 amd64/arm64 构建、测试并发布独立安装包及 SHA-256，再回读公开资产验证。
