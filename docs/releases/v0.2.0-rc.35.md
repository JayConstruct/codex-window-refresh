# v0.2.0-rc.35 修复模型目录查询误计入用户请求

CPA 查询模型目录（如 `/v1/models`）时也会发出请求完成事件，但没有模型、调用方、账号选择或执行用量。此前后台会将这种孤立完成事件新增为用户模型请求，表现为“未标记项目 / 调用方未知 / 模型未记录 / 0 次尝试”，导致运行记录数量高于计费插件基于用量事件的记录。

后台不再仅凭完成事件、TraceID 或 HTTP 状态创建用户模型请求。已经观测到的业务请求仍可由缺少元数据的完成事件正常结束；只在完成时观测到模型、或有精确关联选择/执行的请求继续保留，不因调用方、项目或用量缺失而排除。

历史中缺少业务请求证据的空记录保留原始观测，但退出用户列表、详情、筛选建议及分流汇总。页面提示保留范围内未计入的数量，不追溯断定每条都是目录查询。用户请求仍包含执行前拒绝、取消等情况，数量不要求与计费记录完全相等。

后台和客户端安装包为 **v0.2.0-rc.35**，接入层保持 **v0.2.0-rc.32**，数据库保持 **schema 12**。从 rc.32–rc.34 升级时，安装器确认接入层文件完全一致后可仅更新并重启后台；完成后强制刷新网页。从 rc.31 或更早版本升级仍须显式 `--restart`。已有账号、规则、任务和发送防重记录保留，客户端启动器行为沿用 rc.31。

回归覆盖模型目录成功及失败完成事件、缺少调用方的真实模型请求、缺少元数据的业务完成事件、历史空记录过滤和精确关联尝试保留。本地 Go 测试、vet、文档及网页检查和 71 项原生端到端测试通过；发布工作流另在 amd64/arm64 执行构建、竞态及安装器测试、浏览器验证和公开安装包回读。测试使用模拟账号和响应，不等于真实账号或生产负载验收。
