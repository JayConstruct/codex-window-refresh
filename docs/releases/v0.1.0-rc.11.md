# v0.1.0-rc.11 测试版

手动查询始终可用，自动查询和页面自动刷新改为主动开启；新增单账号手动唤醒，并修正未启动窗口的倒计时展示。

## 本次变化

- 移除“允许手动查询”权限开关。单账号与批量查询无需开启权限，旧策略中的 `quota_query.manual: false` 不再阻止或取消查询；仍需管理认证、后台运行及额度接口就绪。
- 新策略默认关闭自动额度查询和自动模型唤醒。已有策略中显式开启的设置保留。页面自动刷新默认关闭，在总览手动勾选后每 5 秒读取快照；关闭、断开或重新打开页面后不再自动轮询。
- 账号卡片新增“手动唤醒此账号”，确认消耗额度后，仅使用已保存的模型与消息请求该账号。无需开启自动唤醒，但要求 CPA 插件启用、账号未暂停、模型与宿主能力就绪。发送前查询额度，检查前台占用、账号代际、退避、发送间隔与重复送达；不自动补发。
- 仅查询返回的完整五小时、100% 剩余额度保持未知窗口，不产生本地倒计时。页面只对已确认活跃窗口显示服务端重置倒计时。手动唤醒请求成功也不能代替服务端窗口证据，未知送达和重启均继续抑制重复发送。
- 状态读取恢复成功后，自动隐藏对应的超时或网络错误提示，不误清配置校验、保存冲突或其他操作错误。
- 增加统一一键安装/更新入口，自动处理 Debian 12/13 依赖、已有 CPA 与已核实 systemd 服务；保留策略和状态，旧升级脚本委托同一入口。

## 安装或升级

已有 CPA 的 Debian 12/13 服务器执行：

```sh
curl -fSL https://raw.githubusercontent.com/JayConstruct/codex-window-refresh/main/scripts/install.sh -o /tmp/codex-window-refresh-install.sh && sudo bash /tmp/codex-window-refresh-install.sh --version v0.1.0-rc.11
```

root 会话可省略 sudo；命令要求已有 curl，缺失时先安装 ca-certificates 和 curl。升级保留已有策略、模型及窗口状态，默认重启已核实的 CPA systemd 服务，可能短暂中断请求；使用 `--no-restart` 可稍后手动重启。CPA 路径或服务无法唯一识别时，请沿用 `--cpa-dir`、`--service`、`--user-service`、`--user` 等参数。Docker 部署请按安装指南替换容器内插件，不使用 systemd 一键入口。

重启 CPA 后刷新管理面板。先执行单账号额度查询；需要手动唤醒时，在“模型唤醒”填写并保存实际支持的模型与消息，再确认账号卡片的手动唤醒。自动刷新关闭时，可点击“更新页面数据”查看进度和结果。

## 验证与边界

本地全量 Go 测试、race、vet、面板逻辑测试和原生 ABI 加载检查通过。新增回归覆盖完整额度不启动窗口、精确单账号唤醒、自动唤醒关闭时手动操作、确认取消、错误恢复、前台占用、凭据代际变化、持久化失败、未知送达与重启抑制。发布流程要求 Chromium 浏览器检查及 Linux amd64、arm64 各自通过构建、安装器和原生加载验证，再上传安装包及 SHA256SUMS。

仍要求 CPA ABI 1 / RPC schema 6。尚未在真实 CPA 宿主或生产账号上联调；宿主同步 C 回调若完全不返回，Go 超时不能强行中断。窗口启动只以服务端额度证据为准，插件不自行刷新 OAuth。前台请求与后台发送之间仍依赖宿主提供的安全能力，无法宣称消除全部竞态。
