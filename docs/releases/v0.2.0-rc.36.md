# v0.2.0-rc.36 手动并发唤醒、响应额度核实与 Key 名称管理

手动唤醒的额度预检与后续核实查询不再继承批量随机延迟，也不会等待同账号尚未到期的批量查询。唤醒检查优先进入额度查询队列；新鲜完整额度仍可直接复用，发送前保留账号绑定、禁用、活动和额度准入检查。

不同账号可同时执行唤醒，与候选生成共享最多 4 个模型执行名额。页面按账号跟踪提交、核实和未知状态；一个账号的任务不会锁住其他账号。原生接入层按账号保留流所有权，旧流未关闭或关闭失败时只阻止该账号的新模型调用，防止重复发送。

唤醒优先解析宿主返回的额度响应头与流中的结构化 `codex.rate_limits` 事件，在结束发送的同一事务中按绑定和字段水位更新余额及上游重置时间。新鲜五小时活动窗口证据充分时，直接完成核实并省去额外额度查询；缺失字段保留原有观测，旧响应不能覆盖新数据。HTTP 200、token 用量、回复文本或满额占位不足以确认窗口启动，此时仅补充只读查询；未知模型请求不重发。

运行记录的用户请求列表及详情显示打码 API Key。详情新增“修改名称”，支持保存与清空，与同一浏览器、同一 CPA 地址下的管理中心共用名称存储。刷新记录、切回页面或重新进入时核对 CPA Key 清单；Key 被删除后撤下打码值及改名入口。保存前检查 Key 身份和名称冲突，失败保留草稿。完整 Key 仅在内存中用于身份匹配，不写入插件后台、页面 DOM 或额外存储；名称不跨浏览器或设备同步。

后台、客户端安装包与原生接入层均为 **v0.2.0-rc.36**，数据库保持 **schema 12**。从 rc.35 或更早版本升级必须使用 `--restart`，同时更新后台与接入层并重启 CPA；完成后强制刷新网页。已有账号、规则、任务与未知发送防重记录保留，客户端启动器行为沿用 rc.31。

本地回归覆盖多账号并发和同账号防重、无随机延迟、响应额度直接核实及字段合并、回执丢失不重发、CPA 名称编辑和冲突、Key 删除及桌面/手机布局。发布工作流在 amd64/arm64 构建和测试，发布独立安装包及 SHA-256 后回读公开安装包验证。测试使用模拟账号与响应，不等于真实账号或生产负载验收。
