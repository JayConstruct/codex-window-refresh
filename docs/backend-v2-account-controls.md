# V2 账号开关与显示偏好

## 官方接口依据

核对 CPA 固定提交 `3de4e248f6bb12fc7dfafb183404f3b248578922`，来源为官方仓库，不复制完整上游源码或 OAuth 客户端信息：

- [管理路由](https://github.com/router-for-me/CLIProxyAPI/blob/3de4e248f6bb12fc7dfafb183404f3b248578922/internal/api/server_management.go)：`GET /v0/management/auth-files` 读取目录，`PATCH /v0/management/auth-files/status` 修改启用/禁用状态。
- [状态处理器](https://github.com/router-for-me/CLIProxyAPI/blob/3de4e248f6bb12fc7dfafb183404f3b248578922/internal/api/handlers/management/auth_files_fields.go)：请求包含必填 `name`、布尔 `disabled`，以及可选的 `auth_index` 身份限定；正常成功返回 `{"status":"ok","disabled":true}` 或对应的 `false`。
- [账号目录及查找](https://github.com/router-for-me/CLIProxyAPI/blob/3de4e248f6bb12fc7dfafb183404f3b248578922/internal/api/handlers/management/auth_files.go)：目录提供 `id`、`name`、`auth_index`、`provider`、`disabled`、`runtime_only`。给定 `auth_index` 时按账号 ID/文件名与索引共同匹配，不以展示别称或列表位置选账号。

仅核实上述源码合同不代表所有部署都支持接口。不支持、目录身份不唯一或仅运行时账号须明确拒绝修改，不改用上传认证文件、下载凭据或试发模型请求来实现开关。

## 状态修改边界

插件从当前 CPA 页面使用同源管理认证直接操作真实认证文件开关，沿用反向代理前缀；不把管理密钥传给独立后台或保存到显示偏好。**不能使用 `POST /auth-files`，它是上传/替换认证文件，不是状态补丁。**

操作前按原始账号 ID 唯一读取目录，核对真实文件名、索引、提供方和运行时标记，再明确确认目标。PATCH 只包含真实目录身份和目标 `disabled`，不夹带提示词、别称、额度或认证内容。启用会使账号重新参与 CPA 调度，已开启的自动规则也可能恢复执行，不能把开关当作无副作用的显示操作。

PATCH 后重新读取 CPA 核实目标状态；请求失败或返回不确定时不自动重发，只读核实原目标。CPA 在修改状态后执行持久化 hook 时仍可能失败，所以不能仅凭 HTTP 错误断言修改未发生。外部页面可并发修改状态，该接口不是状态 compare-and-swap；身份前后核对也不保证消除所有外部变更窗口。

禁用不清除插件的发送防重记录，启用不解除未知发送保护，不自动创建模型测试。插件额度状态与 CPA 开关有独立含义：额度耗尽/受限不等于认证文件禁用，开关不能伪造恢复额度。启停确认以 CPA 目录为准，后台账号状态继续由原同步机制读取。

## 显示偏好

账号支持原始显示、打码及本地别称。偏好只保存在当前浏览器，并按 CPA 地址和路径隔离；不修改真实账号 ID、认证文件名、后台数据库任务或模型请求身份。无别称时使用打码回退；选择别称时只使用已知的唯一账号映射，显示值冲突时拒绝操作，不猜测真实账号。

这是界面显示保护，不是数据匿名化或访问控制。原始账号仍存在于已认证的后台响应、网络请求和数据库中；主动编辑实际账号 ID、复制任务 ID 或查看原始业务响应时仍应注意泄露风险。使用浏览器共享设备时也要保护本地偏好及管理会话。

## 唤醒诊断与跳过

唤醒提示按实际检查结果区分禁用、宿主暂不可用、账号不存在、身份歧义、状态同步不新鲜及绑定缺失/变化。旧记录若只有通用代码，应说明无法核实具体原因，不能将其断言为绑定变化。

`skipped` 表示规则或安全条件下未执行唤醒，不作为错误展示或计入错误数；可正常查看跳过原因。真正的失败与未知发送结果仍需关注，不能为了隐藏错误而把未知任务改成跳过。
